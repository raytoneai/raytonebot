# UI/UX 实施与验收 · 2026-10-22

按用户“避免不必要的次级标签和说明，让布局表达含义”的要求，延伸原组件完成四项优化：

- 审批采用原生单选控件与唯一确认按钮；默认不显示重复提示，仅持续授权显示范围，失败/提交反馈保留。问题与频道配置使用原默认分支。
- 插话为次级动作，排队发送保留文字/队列图标，停止独立。窄宽度允许工具区与提交区分行。
- 输出默认 56/44 分栏，手动调整跨重开与刷新保存，坏数据/存储不可用不影响打开。文件路径留在标题悬停提示，扩展名已说明类型时不重复标签。
- 搜索零结果与空目录分别提示；输入框清除按钮保持输入焦点。

## 验证

- `npm run build` 通过；仅既有大 chunk 提示。
- `npm test`：446/446 通过，包含新增的比例恢复、损坏数据与存储受限检查。
- 相关审批身份、焦点和分栏测试 4/4 再验通过；修改范围 `git diff --check` 通过。
- `fixtures.json`：20 个内置场景，1280px 下渲染正常、无页面横向溢出。
- 浏览器实际验证审批默认/持续授权、方向键选择、390px 布局和亮暗主题。CDP 仅拦截本机审批 fetch，以受控 503/200 响应验证选择不发送、双击仅一请求、等待中禁用、失败保留选择、拒绝重试成功后关闭。未向真实主机批准工具。
- `composer-check.html` / `composer-check.tsx` 是本目录的隔离验证页，只渲染现有 ComposerFrame 并记录回调；不调用后端或存储草稿。依次操作结果为 queue → steer → stop，无额外 send；停止保留草稿，队列暂停；390px 中文亮色/日文暗色无溢出。
- 实际对话 HTML 预览：1280px 窗口输出约 436px；调整为约 386px 后，重开和刷新宽度一致。搜索无匹配提示准确，清除返回空查询并聚焦输入。
- 浏览器控制台 error 为 0。临时主题已恢复亮色。
