## 已修复

| 顺序 | 用户可感知的变化 | 验证 |
| --- | --- | --- |
| P1 准备阶段撤销 | 模型准备中停用/删除后不会再启动，关闭再开也不会复活旧请求；已接受运行仍由原对话停止 | HTTP + 真实控制器覆盖三种操作，受控配置屏障和晚到拒绝覆盖失败计数/取消 signal |
| P1 真实终态恢复 | 例行记录写盘失败后，按已保存会话的准确 runId 修复最近记录；恢复后不再假显示运行中/中断 | 实际 `.tmp` 路径阻塞，成功/取消的同进程及重启恢复；错误只计一次，活跃/缺失/不可读/合成中断不猜测 |
| P2 计时边界 | 启用/改 cron 或时区从未来场次生效，不回补停用时间或伪造漏跑；墙钟回拨后新任务正常触发 | 可控时钟五场景，含旧格式首轮建基线与已接受 occurrence 防重 |
| P2 结果入口 | 首次准备失败没有真实会话时禁用打开；以前有结果仍可打开原对话 | 原 Routines owner 真实浏览器点击，覆盖无会话、历史成功、运行中、已完成 |

无新服务、数据库、字段 schema、面板、模型或权限变更。计时仍为 30 秒检查、最多 3 分钟运行时延迟窗口，保留 cron/时区语义、失败停用和现有历史。没有不确定任务的自动重放，也没有业务内容去重。
