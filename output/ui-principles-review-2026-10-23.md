# RaytoneBot UI 原则审查

日期：2026-10-23。审查当前工作树，未修改产品代码。

## 结论与范围

值得优化，优先顺序为文案与重复信息、字号、颜色体系、装饰与动效。现有聊天布局、Bot 头像、按需展开设置和统一输出区已符合克制的方向，无需重做布局。

浏览器实看本机 1280×720 亮色界面的已有聊天、输出文件列表、设置中的模型服务、权限和 IM 频道。核对了 DOM、实际计算字号与对应源码。没有发送消息或修改权限、模型、频道配置。暗色、手机、缩放、完整键盘与屏幕阅读器流程未验；没有进行真实模型或全部 devtools 场景回归。本报告是设计审查，不是功能验收。

## 对照 11 条原则

| 原则 | 当前证据 | 建议 |
| --- | --- | --- |
| 1 不用中点分隔 | 工具摘要、模型服务、频道、例行任务和 MCP 列表存在；聊天与设置已实看 | 句子使用自然标点；独立元数据使用 gap 排版。不要全局替换用户消息、文件内容或代码中的字符 |
| 2 减少解释 | 模型服务页首解释四种引擎的适用范围；频道页首讲主动连接和公网地址 | 日常列表保留状态和操作；连接技术说明移入对应配置步骤或按需帮助 |
| 3 文案贴合受众 | 设置混用 Agent、Bot、成员；“全部允许”说明又说部分操作仍会询问；“只读路径”说明允许审批后修改 | 根据真实权限语义命名，统一助手身份称呼，缩短非关键说明；品牌及引擎专名保留 |
| 4 Radix Colors | themeTokens.ts 自定义色值和混色；没有采用 Radix 色阶映射 | 保持现有语义 token 接口，将亮暗界面色映射到 Radix；品牌头像、第三方标识、用户产物应单独界定范围 |
| 5 对齐和同心圆角 | 主视图基线总体整齐；设置列表与外层容器存在多套局部圆角值 | 按实际相邻容器核对，外圆角减去内距得到内圆角；图标按视觉重心修正，不凭 CSS 数字判定错位 |
| 6 0.5px 边框 | 当前主要采用 1px，部分描边由 box-shadow 实现 | 可先试静态分隔线和面板边线；焦点环、状态标记、可拖拽分隔线按辨识度保留；需亮暗及不同像素密度实看 |
| 7 减少动画 | 基础时长 120/160/240ms；侧栏点击缩放；图像生成另有弹性循环和 520ms 显现 | 清理无信息价值的缩放及重复过渡。保留运行反馈与 reduced-motion；无需把快速反馈统一放慢至 250ms |
| 8 至多四档字号 | 聊天与输出同屏采样出现 11/12/12.5/13.5/14/15px 六档；历史数量为 11px。权限设置实际四档 | 产品控件建议先收敛到 12/14/16px，必要时标题 18px。Markdown 内容层级和数学公式需单独评估 |
| 9 减少决策 | 设置集中在单一入口，列表按需展开，方向正确；权限默认项与显式相同模式并列，说明重复；8 个设置导航平铺 | 明确“跟随主机”的继承含义；现有导航用间距分组即可，不必新增中间页面或强制步骤 |
| 10 减少圆角阴影 | 侧栏选中 Bot 与设置选中项均叠加背景、1px 阴影描边、小阴影 | 选中态用背景和字重即可；浮层保留阴影。Markdown 引用边线具有语义，不应当装饰卡片一并删掉 |
| 11 减少眉题 | 实看页面没有普遍的大写装饰眉题；输出区“产物”页签下再次出现同名标题 | 删除重复“产物”标题；侧栏 Agent 是分类标题，低优先级评估；审批“需要授权”传达状态，不按重复眉题处理 |

## 五项优先工作

### P2 文案与信息优先级

- 模型服务的四引擎说明：`src/i18n/copy/settings.ts:268`。建议列表首屏省去，进入具体 Bot 的模型来源选择时再解释。
- IM 的服务器连接说明：`src/i18n/copy/settings.ts:325`。可缩为“连接聊天软件，在其中使用助手。”；技术配置要求在展开对应平台时出现。
- 权限“只读路径”：`src/i18n/copy/settings.ts:320` 附近，应根据“可读，修改需确认”表达实际语义。凭据限制和授权范围仍是必要信息，不能为了简洁隐藏。
- 输出重复标题：`src/components/agent-preview/outputframe/OutputContent.tsx:96`。
- 工具摘要：`src/components/agent-preview/chatframe/ToolRunSummary.tsx:23`。建议默认显示“执行了 4 项操作，1 项失败”，操作种类放到详情；失败数量不可被精简掉。
- 设置元数据中点：`src/components/settings/SettingsDialog.tsx:291`、`:540`、`:804`、`:905`。使用独立字段和间距，不换成另一种装饰分隔符。
- 兼容注意：`src/components/shell/ShellExtras.tsx:297` 仍通过 `providerLabel.split(" · ")` 提取标签。清理文案时必须同步检查该调用关系，不能只批量替换字符串。

适用操作：`/clarify`、`/distill`。

### P2 字号收敛

基础 token 位于 `src/styles/app.css:51`，五档为 11/12.5/13.5/15/18px；另有组件局部字号。`src/styles/app.css:12997` 的历史数量实际显示为 11px。优先统一产品控件，避免为了“只准三档”破坏长文标题和代码阅读。

适用操作：`/typeset`。

### P2 颜色按用途统一

`src/theme/themeTokens.ts:54`、`:98` 起使用自定义状态色、表面色和混色。Radix Primitives 的存在不代表已采用 Radix Colors。

建议沿用现有 `surface/text/border/accent/status` 结构，候选为中性 Slate、强调色配合既有品牌方向、状态色 Red/Green/Amber。色阶用途：1–2 背景，3–5 控件及悬停/选中，6–8 边框，9–10 实心强调色，11–12 文字。实际对比度应在组合后的界面复测；Amber 9/10 不应默认配白字。

来源：[Radix Colors 官方使用规范](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)。

适用操作：`/colorize`。

### P3 去除多余装饰与动效

`src/components/shell/shell.css:36` 的点击缩放、`:37` 的选中阴影，以及 `src/components/settings/settings.css:76` 的选中描边加阴影可以收敛。Bot 头像属于已确认的品牌个性，不应按通用后台模板全部去掉。动画数量与用户实际看到的动画不是同一个指标。

适用操作：`/quieter`。

### P3 对齐、圆角与细边线

当前未发现足以判定为主要缺陷的整体错位。设置与输出的局部内边距、圆角和描边应在前面几项稳定后统一复查。0.5px 适合测试细分隔线，不能替代焦点可见性和状态可辨识性判断。

适用操作：`/polish`。

## 设计判断与可用性初评

没有明显的通用 AI 营销页模板问题：没有成排指标卡、渐变标题或重复大写眉题。Bot 头像提供可识别性，主对话任务清楚，工具细节可以展开，设置和输出有明确归属。主要问题来自多轮迭代后局部规范不一致。

以下为有限视图的启发式初评，0–4 分，不是可用性实验或完整可访问性认证。

| 启发式 | 分数 | 依据与限制 |
| --- | --- | --- |
| 状态可见性 | 3 | 状态文字、失败计数清楚；本次未验证实时变化 |
| 符合用户语言 | 2 | 权限标签与例外说明有理解成本，技术说明较多 |
| 控制与退出 | 3 | 设置与输出可关闭，操作入口清楚；未验证全部取消流程 |
| 一致性 | 2 | 字号、中点、助手称呼和色值来源不一致 |
| 错误预防 | 3 | 权限选项保留边界说明，未填凭据的频道开关禁用；执行未测试 |
| 识别优于回忆 | 3 | Bot 名、历史分组和设置列表清楚 |
| 效率 | 3 | 可展开详情，常用操作近手；未验证完整键盘路径 |
| 简洁 | 2 | 重复产物标题、技术说明及局部过度装饰 |
| 错误恢复 | 2 | 有失败状态和相关文案，恢复行为未实测，暂不高评分 |
| 帮助 | 2 | 配置帮助存在，但呈现位置和篇幅仍需收敛 |
| 总计 | 25/40 | 有可用基础，细节一致性与信息密度待改善 |

认知负担八项检查：主任务单一、相关内容分组、层级、逐步决策、无需跨屏记忆这五项基本通过；设置导航分组、可见选择数量、帮助的渐进披露三项有改进空间，暂评中等。八个导航项并不自动构成故障，也不应机械缩减到四项。

使用情景复核：

- 熟练的项目所有者：模型服务和 IM 列表的常驻解释占据注意力；应让状态、名称和操作优先。
- 较久未使用后返回的用户：对“全部允许”和“只读路径”需读后面的例外才能准确理解，应优先修正文案。
- 小字阅读或键盘辅助用户：11px 历史数量偏小；频道开关的无障碍名称含“已连接”，但当前可见状态为“未启用”，存在语义不一致，建议单独修正。完整读屏流程尚未验证。

实施建议按 `/clarify` → `/distill` → `/typeset` → `/colorize` → `/quieter` → `/polish` 排序。均应延伸现有 owner；本轮只交付审查，不涉及架构、权限行为或主题偏好变更。
