## 已确认的问题

1. **P2：干净发布仍受工作区依赖影响。** `buildReleaseFromHead` 复用原 `node_modules`，本地 file 依赖因此解析到原工作区 vendor。主代理用隔离 Git 项目调用真实发布函数，得到 `dirty=false`、bundle 为 `DIRTY_WORKTREE`、归档 vendor 为 `CLEAN_HEAD`。这是上一轮干净发布修正未覆盖的构建输入边界。
2. **P2：卸载后的迟到列表重新建立订阅。** 新卸载清理只取消已存在的控制器，未返回的会话列表仍可调用 `followRun`。独立审查用目标提交中的实际函数和受控 HTTP 边界复现：卸载后新建一个未取消的 `/live` 订阅。属于生命周期修正遗漏，不能描述为新引入的行为。
3. **P2：旧 bridge 失败误删新缓存。** 删除开始释放 bridge 后，尚未完成的旧 `state` 请求与复用 ID 的新配置可能并存。旧 Promise 的 catch 无条件删除同 ID 缓存，随后读取丢失新配置并泄漏替代 bridge。独立隔离复现得到模型从配置值退回默认、共创建三个 bridge。
