# AgentMatrix 承载 RaytoneBot：最小改造需求

日期：2026-10-19。交付对象：AgentMatrix 平台项目与 RaytoneBot 项目。

状态：需求交接稿；本轮仅编写文档。以下任务和验收均为后续工作，未实施、未创建测试资源、未部署，也不构成操作生产资源的授权。

## 1. 目标与边界

让一个现有 RaytoneBot 实例运行在自有 AgentMatrix 平台上，保留现有运行时和主要功能，并使完整应用数据在更换机器后可恢复。用户使用稳定地址进入；无人打开网页时，IM 和例行任务仍能运行。

首期资源单位为**一个逻辑部署实例、一个持久 Workspace、一个当前运行的 Environment**。界面里的多个 Bot 和多个对话不各自创建平台资源。重建可以更换 Environment ID，但逻辑部署身份、持久数据和用户入口保持对应关系。

保留以下内容：

- React/Vite UI、现有 Node HTTP 主机、Pi / Claude Code / Codex 三引擎及既有模型选择。
- RaytoneBot 自有事件、对话/原生上下文、群聊、审批、记忆、MCP、文件、浏览器与例行任务语义。
- 现有主动出站 IM 连接器、独立 Agent/browser UID、网络隔离和凭据保护。
- 不确定执行结果不自动重放；进程重启后的未完成轮次仍按现有规则标为中断/待核对。

首期不做：托管 Agent Session 替换、接入平台 Event Bus/Channel Runtime、通用 PaaS、多实例编排、自动扩缩容、租户任意 root/镜像入口、通用远程终端、应用数据库替换、跨设备配置同步、在途任务自动恢复。只有固定应用部署确有需要时，才新增对应接口；已有能力优先复用。

## 2. 基线与成功标准

评估基线是 2026-10-19 已核查的 SDK `0.11.0`、包合同 `0.154.0`、在线 Platform OpenAPI `0.155.0`。这是已查证版本记录，不是未来版本承诺。AM-00 开始时重新核对最新版 SDK 与目标平台，固定兼容组合，不顺带升级 RaytoneBot 引擎或默认模型。[评估与证据](agentmatrix-platform-research-2026-10-19.md)

| 当前痛点 | 首期必须达到的结果 |
| --- | --- |
| AgentSphere 暂停后访问返回 502，需要外部唤醒 | 稳定入口可在授权后触发允许的恢复，等待真实应用 health；用户不需要重新取得临时预览 URL |
| 运行窗口封顶，续期可能返回成功但未延长 | 平台报告实际租约状态并执行确定的续租/换代策略；常驻策略不能把“请求成功”当作续租成功 |
| 暂停保留期不明、实例丢失依赖最近外部备份 | 全部必要状态进入明确的持久化/备份边界，完成正常换机和原宿主不可用的恢复验收 |
| 无人访问时 IM/例行任务可能随休眠停下 | 首期使用显式常驻策略，跨实际空闲和租约窗口验证后台工作；不依赖网页流量保活 |

完成标准：P0、P1 均通过；应用功能回归和数据恢复证据齐全；明确异常场景允许的数据丢失窗口与恢复时间。仅静态页打开、health 200、Workspace 可列目录均不算完成。

现有服务入口为 HTTP `5188`，应用健康接口为 `GET /__agentcanvas/pi/health`，云端需经过现有鉴权。模型代理 `5190`、浏览器代理 `5191`、CDP `5192` 保持环境内部访问，不作为对外服务端口。TLS 可由平台入口终止，按实际部署确认转发地址。

## 3. 责任划分与优先级

P0：确定宿主可行性和双方合同，应用迁移依赖它。P1：首个正式实例切换前必需，不是可延期优化。P2：首期明确不实施。

| 责任 | AgentMatrix 平台侧 | RaytoneBot 侧 |
| --- | --- | --- |
| 机器和存储生命周期 | provider/template、Environment、Workspace、租约、宿主故障、资源身份映射 | 提供应用版本、依赖、路径和恢复要求 |
| 服务生命周期 | 每个环境代次的初始化/启动入口、实际状态、日志入口；防止重复启动部署 | 复用现有 supervisor 管理 Node 和子进程；提供启动/停止/health 约定 |
| 数据恢复 | 持久卷、可确认的持久化边界、实例外备份位置/调度、机器重建 | 一致归档、数据校验、原生上下文/权限恢复、功能核对 |
| 入口与权限 | 稳定路由、用户授权、内部凭证、环境绑定和恢复等待 | 保留应用鉴权、Host/Origin 和 handoff 约束，适配可信入口 |
| 业务执行 | 不接管应用轮次、定时业务、审批或 IM | 现有运行时继续负责；不接平台托管 Session |

**管理动作只有一个执行方。** 平台负责新环境的续租、常驻和重建；已有 `control` 若保留，只作用户入口/平台调用方，不再用旧 AgentSphere keeper 同时续租同一实例。备份计划首期由平台侧触发一次，应用负责产出归档。平台不再另加一套与现有 supervisor 竞争的 Node 重启循环。

## 4. 平台侧任务

### AM-00 · P0 · 核实现有能力并冻结实施基线

先查平台源码、provider 配置和实际模板，分别列出“已有可复用”“仅需配置”“必须开发”。模板别名 `agentmatrix-v1` 只作线索，要记录解析后的 provider、template ID/构建版本、区域及资源规格。

必须交付：

- SDK/API 版本组合；受支持的部署控制路径；模板、系统工具和权限实测清单。
- 单实例存储拓扑、数据挂载方案、实际容量/inode 限额、文件语义与远端持久化确认方式。
- 常驻策略、实际运行窗口、续租行为、故障启动流程；启动/恢复时限与失败状态。
- 异常恢复 RPO（最多丢失多长时间的数据）、RTO（多久恢复可用）、卷/备份保留期的**具体值与测量起止点**。由平台依据实际实现提出、双方在 P1 验收前确认，不用“永久”“尽快”替代数值。
- 独立测试资源计划。namespace 隔离不等于获得额外配额；当前 3 Workspace/tenant、默认 1 Environment/user/tenant 的约束须纳入安排，不删除现有生产资源来腾测试位置。

验收：每个后续任务有可调用的既有能力或明确开发项；上述参数有记录，无模板同名即兼容、接口 2xx 即实际完成的推断。无需为当前单实例先扩配额。

### AM-01 · P0 · 确定性的发布与服务控制

提供固定应用包/模板的部署、启动、停止、重启、状态和有界日志能力。实现可复用平台内部 provider/E2B 调用与现有脚本，不强制新增通用 exec/upload 公共 API，不通过模型执行提示词来部署。

应用包应可容纳完整发布产物和冻结的 vendor 构建文件，不依赖 Workspace 单文件 1 MiB 接口逐文件拼装大归档。版本与内容摘要可追溯；仅允许可信部署方提供的版本和配置。部署/重建凭据留在受信任平台侧，应用所需凭据单独注入私有文件，不进入 Agent 环境或日志。

保留既有 `user`、`raytone-agent`、`raytone-browser` 隔离；可在管理员模板/受控初始化中安装 sudo/setpriv、nft、ACL、匹配的 Node/CLI、Python、rg/fd、Chromium，按实际浏览器模式提供依赖。Agent 无需 root。旧应用包回滚不能自动覆盖较新的业务数据。

验收：同一意图重复提交不创建第二个实例/进程；客户端断线后可查询原操作结果；重启后仅一个 supervisor；失败安装可定位阶段且不误报 ready；未授权调用被拒绝。模板内用真实 UID 验证文件/网络隔离和浏览器启动，不以二进制存在代替运行验证。

### AM-02 · P0 · 应用状态的持久存储与路径映射

按第 7 节覆盖全部状态。优先在受控初始化中把持久目录映射回现有绝对路径；允许平台内部实现固定映射，不要求先发布通用多挂载点 API。不满足实际文件语义时，再与 RT-02 共同选择路径改造。

支持应用需要的文件 owner/group、权限/ACL、原子替换、CLI JSONL 追加，以及浏览器 profile 的数据库与锁语义。私有目录在挂载目标及原始存储路径均不可被 Agent UID 绕路读取，不能只在 UI 隐藏。确认持久卷未挂载时拒绝按空目录启动新状态。

验收：应用实际 UID 可完成必要文件操作；错误 UID 不能读私有数据；正常写入、改名、追加及浏览器关闭后再打开通过。停写并确认持久化后，在新 Environment 重新绑定同一 Workspace，文件内容、属主/权限与应用引用一致；当前环境删除不删除卷。原环境未停止/写入身份不明确时，不启用第二个写入实例；首期可用串行维护流程满足，不强制分布式锁服务。

### AM-03 · P1 · 常驻、租约与故障恢复

为该逻辑部署提供显式常驻策略，首期不建设按访问量自动休眠产品。没人开网页、平台无托管 Session、应用无当前轮次时，IM 与 routines 仍应工作。端口监听/health 只表示就绪，不能当作业务 busy。区分期望运行和人工停止/维护状态，后者不能被保活或 bootstrap 擅自拉起。

平台核实续租后的真实期限，给出下一次动作与失败原因。若 provider 有不可延长的运行上限，必须在界限前实施有记录的续租或受控换代；不能暗中杀死工作，也不能宣称零中断。换代停机预算纳入 AM-00；优先等待应用空闲，无法满足时报告受限状态，由维护流程处理。

验收：无人访问期间越过实际 idle 阈值，IM 入站和例行任务正常；至少覆盖一次实际租约边界并记录期限。短窗口注入测试不能代替最终真实窗口观察。应用进程崩溃按原 supervisor 恢复；整机丢失按平台流程重建并恢复数据；结果不明的业务动作不自动重发。

### AM-04 · P1 · 稳定、鉴权的服务入口

提供稳定 HTTPS 地址，绑定逻辑部署而非短命 Agent Session 或物理 Environment ID。底层连接凭证可短期更新，但用户书签和应用 origin 不随换代改变。复用平台既有路由/鉴权设施；不要求自定义域名管理产品，也不把超长期 bearer 预览链接当正式鉴权方案。

入口访问被允许恢复的暂停实例时，应在鉴权后发起恢复，并按真实应用 health 有界等待；超时显示可重试的明确状态，不创建模型轮次。人工停止/维护不因访问自动撤销。需保留 HTTP 流式回复、SSE、WebSocket、Range 下载和上传能力；Host/Origin、Cookie 与转发头规则交给 RT-03 对齐，不能靠关闭应用检查接通。

验收：跨内部凭证过期、进程重启和环境重建，原书签仍进入同一实例；未登录/无权访问不能获得服务或触发其启动。归档无关托管 Session 不影响服务。重连不重复提交用户 prompt；入口不缓冲整段回复。应用现有 10 MiB 上传、代表性 100 MiB 工作文件下载及媒体 Range 读取通过。

### AM-05 · P1 · 持久化确认、独立备份与恢复操作

提供可解释的持久化确认：明确 guest 文件写入、卷本地发布、远端可恢复数据分别代表什么。仅调用 `sync` 或收到文件 API 204，不能作为远端恢复证明。

复用平台已有存储/调度能力，保存能在原实例及原宿主不可用时读取的独立备份；仅把归档存回唯一业务卷不算独立备份。应用归档由 RT-02 生成和校验。可先提供受控恢复操作，无需图形化“一键恢复”。备份频率和保留期采用 AM-00 确认值；每次正式迁移/覆盖前额外保留可验证备份。失败可见，报告最近成功备份及其时间，不把失败尝试更新时间当成功。

验收：受控停写且完成持久化确认的验收数据在正常换机后零丢失；原宿主不可用时能恢复至承诺的数据点，实测 RPO/RTO 不超过 AM-00 约定。损坏或不完整归档被拒绝，恢复失败保留原可恢复数据。记录实际恢复来源，不能把“同机暂停/唤醒”当作灾难恢复测试。

AgentMatrix 不需要实现 RaytoneBot 的群聊、审批或记忆；RaytoneBot 不实现另一套平台租约/卷管理。若验收发现原有功能本身有缺陷，单独记录基线问题，不能混算成迁移通过，也不借此扩大本需求范围。

## 6. 双方交接合同

以下为必须可观察的业务语义，不是宣称现有 API 已有这些字段，也不指定新端点命名。平台可以用现有 API、内部受控操作或配置满足；AM-00 提供准确调用方式。

| 交接内容 | 最小要求 |
| --- | --- |
| 资源关联 | 稳定逻辑部署标识 → 当前 Environment/代次、Workspace、应用版本、模板版本、稳定 origin；不得按 UI Bot 数量创建资源 |
| 发布输入 | 可校验的应用包/模板版本、非秘密配置、秘密引用或受控注入方式、存储映射；实例范围授权 |
| 操作结果 | 同步完成或可查询的操作标识；区分 accepted/running/succeeded/failed；同一幂等意图不会重复创建/恢复。响应丢失先查原结果 |
| 状态与排错 | 期望运行策略、实际机器状态、实际租约期限、服务 readiness、应用版本、失败阶段、有界日志；health 与“正在处理业务”分开 |
| 数据恢复 | 挂载身份、确认的持久数据点/备份 ID、源版本、摘要、完成时间、恢复结果；未挂载/损坏不可当空状态使用 |
| 控制权 | 平台负责环境生命周期；应用 supervisor 负责子进程；备份调度单一归属；原环境停止确认后才让新环境写同一状态 |

首选受控挂载保留以下路径。平台内部的存储布局可以不同；不能仅靠 symlink 推断兼容，因为既有备份与文件访问存在反链接检查。

| 数据 | 当前路径 | 恢复要求 |
| --- | --- | --- |
| 产品记录、Pi 上下文、记忆、MCP/IM/routine 配置、审批记录等 | `/home/user/.raytonebot/data` | 全目录保留；配置可能包含秘密，保持 bot 私有，不纳入 Agent 普通工作文件入口 |
| 角色/shared 工作文件、附件、产物与角色说明 | `/home/user/workspace` | 保留目录布局、内容与绝对路径引用；不因绑定新卷自动生成空状态 |
| Claude 原生历史与任务 | `/home/raytone-agent/.claude/projects`、`/home/raytone-agent/.claude/tasks` | 与产品记录成套保存；旧 `/home/user/.claude/...` 按实际源数据兼容迁移 |
| Codex 原生上下文 | `/home/raytone-agent/.codex/sessions` | 保留原生会话身份；兼容旧 `/home/user/.codex/sessions` |
| 浏览器登录 profile | `/home/raytone-browser/profile` | 保留私有 owner/权限；先关闭浏览器再做一致归档。恢复后网站会话可能被站点撤销，应区分站点失效与 profile 丢失 |
| 应用代码、依赖、系统用户/防火墙 | `/home/user/raytonebot`、系统路径 | 由固定发布包与模板重建，不作为用户业务数据；新机重新核对隔离 |
| 模型/访问秘密、部署控制凭据 | bot 私有 env 或受信任外部存储 | 按现有秘密边界重新注入；不归档整个 HOME，不让平台管理 key 进入 sandbox 或前端 |
| Bot 名字头像/聊天归属、草稿、部分偏好 | 浏览器 localStorage/IndexedDB/sessionStorage | 不属于 Workspace。相同 origin 原地恢复；变更 origin 时提供明确的一次性迁移/保留步骤 |

备份应包含一致的产品记录、原生上下文和工作文件，不能只存 conversation JSON 或 session ID。初期可在维护窗口停止全部写入者完成归档；只检查 activeRuns=0 不能排除上传、设置或浏览器写入，不声称现有在线 tar 具备跨文件事务性。

## 8. 联合验收矩阵

所有验证先在独立测试资源完成。故障注入、删除测试 Environment、恢复覆盖和真实 IM 发送须在实施阶段明确测试对象与授权；本文件不触发这些操作。

| 编号 | 场景 | 通过标准 | 主责 |
| --- | --- | --- | --- |
| V01 | 固定包部署、重复请求、部署调用断线 | 查回同一操作；一个逻辑实例/一个 supervisor；应用版本和包摘要一致；失败不标 ready | AM-01 + RT-01 |
| V02 | 系统权限和网络 | 三引擎真实只读/写入任务与 Chromium 可运行；按原权限完成批准/拒绝；Agent 读不到 bot/env/profile，不可绕过既有网络边界 | AM-01/02 + RT-01 |
| V03 | 核心业务回归 | 三引擎连续两轮、群聊、停止/审批/始终允许、提问、记忆、MCP、附件/文件/媒体、浏览器接管与下载通过；不改默认模型 | RT-04 |
| V04 | 入口、过期和重连 | 旧书签跨内部凭证到期仍可用；授权恢复等待有界；刷新补齐原事件而不重发 prompt；SSE/WS/Range/上传下载通过，越权被拒 | AM-04 + RT-03 |
| V05 | 无人访问及租约边界 | 覆盖真实 idle 和至少一个租约边界；IM 收发和 routines 触发记录可核对，无因误判空闲导致的停工；正常场次不重复 | AM-03 + RT-04 |
| V06 | Node 重启与同实例暂停恢复 | 已存历史和文件可读；进程重启的未完成轮次按现有语义中断，同实例快照恢复按实际机制处理；不伪造任务成功或自动重放 | AM-03 + RT-04 |
| V07 | 正常换机、重绑同一 Workspace | 停写并确认持久化后更换 Environment；原生 ID、文件摘要、权限、分支和附件一致；三引擎不借 UI 历史重新提示即可续问；浏览器 profile 保留，稳定入口不变 | AM-02/04 + RT-02 |
| V08 | 原宿主不可用、恢复备份 | 不能依赖旧机器读取；从声明的卷/备份来源恢复，实测 RPO/RTO 达约定；损坏备份拒绝，保留可恢复副本；结果不明动作不重放 | AM-05 + RT-02 |
| V09 | 失败保护 | 挂载缺失、权限错误、满盘/写失败、坏配置、bootstrap 失败和续租未生效均有明确失败；不覆盖原数据、不空状态启动、不产生双写 | AM-01/02/03 + RT-02 |
| V10 | 切换与回退演练 | 旧侧先停写/停 IM 和 routines，新侧再启用；失败可定位并按数据版本回退；浏览器配置迁移可核对；无静默丢草稿或重放对外动作 | RT-03/04，平台配合 |

RT-04 同时按实际改动执行现有 build/test、HTTP 入口检查和全部内置 UI 场景；模拟引擎只能验证控制路径，V02/V03/V07 的真实引擎部分不能用 fixture 替代。测试 IM 使用测试账号；浏览器使用可撤销的测试登录，不导出真实登录秘密作为证据。

routines 保留当前漏跑处理：短窗口按既有规则回看，超出窗口跳过，不为了验收新增任意补跑。故障导致的漏跑要记录；不能把恢复后重放业务动作当作常驻测试成功。

每个 V 项提交：代码/包版本、SDK/API/provider/template 版本、资源身份、测试起止时间、操作与观测、通过/失败、脱敏日志或摘要、残留问题。恢复项另带数据清单与摘要、原生会话身份、实际数据点、RPO/RTO；截图只作辅助。

## 9. 实施顺序与放行条件

| 阶段 | 交付 | 放行条件 |
| --- | --- | --- |
| A：核实与合同 | AM-00、RT-01 的发布/依赖清单 | 模板、存储语义、资源额度、控制路径清楚；差距可拆任务，不从同名模板猜能力 |
| B：固定应用跑通 | AM-01/02，RT-01/02；启动 AM-03/04 集成 | V01/V02 通过，可在测试环境使用完整运行时；持久化和权限不降级 |
| C：上线能力验收 | AM-03/04/05，RT-03/04 | V03–V10 全部有结果，P0/P1 无未关闭阻断；RPO/RTO 等具体值已确认且达标 |
| D：单独批准切换 | 固定版本、源备份、切换/回退步骤、责任人和维护窗口 | 由用户另行确认生产切换；本文及前面测试通过不自动授权部署或销毁原资源 |

以下出现任一项，不切换：必须取消 UID/网络隔离才能运行；只能依赖模型提示词启动服务；正式入口仍依赖用户手动换短期 URL；恢复缺原生上下文或私有状态；租约结束行为不清楚；RPO/RTO/保留期无明确值；旧新实例可能双写。

P2 保留：租户通用 exec/终端、自定义镜像发布、多实例配额产品、自动休眠与外部业务调度、图形化恢复、自定义域名管理、跨设备配置同步。它们均不能成为首期完成固定应用托管的隐含前置。

## 10. 交接材料与代码定位
