# 竞品复盘：重点借鉴 Rakazo 的功能与 UI/UX

日期：2026-10-27。本文是调研判断，不是已采纳的开发计划。

## 结论

Rakazo 最值得参考的是把长期助手的能力组织成一条容易理解的使用路径：选一个有职责的 Bot → 在聊天中交代工作 → 看当前进展和需要处理的事项 → 找回产物 → 管理持续执行的任务。

对 RaytoneBot，优先级最高的增量是 **Bot 的任务导向创建与上下文入口、可编辑且可追溯的例行任务、可找回且有来源的产物**。执行过程可以继续做减法，但现有工具折叠、浏览器接管、安全输入和队列不需要重建。

这是基于源码与界面的产品判断，没有双方用户测试支持“Rakazo 整体体验更好”，也不比较模型能力、任务成功率和速度。

上表 Rakazo 的实现性断言对应[一手来源笔记](rakazo-primary-sources-2026-10-27.md)中的源码；模板名称、RaytoneBot 入口与实施次序均是本报告建议。Rakazo 的 Test run 实际会执行任务，不能借成“无副作用的模拟测试”；RaytoneBot 沿用“立即运行”的明确语义。

### 1. 创建流程：让用户先回答“请它负责什么”

现有 [BotEditor](../src/components/shell/BotEditor.tsx)已经能设置职责、性格、长期要求，并折叠模型与能力；可借鉴的是减少空白表单和初次理解成本。创建研究 Bot 后，欢迎区可以出现“比较两个方案”“核对资料来源”这样的任务起点，点击先填入草稿，用户仍可编辑后发送。

保留引擎与工作区的真实关系说明。RaytoneBot 的同引擎 Bot 共用角色工作区，不能借用 Rakazo 的 Private computer 文案暗示隔离已经存在。头像有品牌价值，可继续保留；优先呈现职责的建议不等于删除自定义外观。

### 2. 例行任务：从“能运行”到“能放心持续使用”

当前 UI 直接显示 cron 字符串和时区，详情可看指令、开关、最近状态、立即运行与打开对话，但没有编辑和多次运行记录入口；[RoutineView](../src/pi/routineTypes.ts)保存 `lastRun`，[useRoutines](../src/runtime/useRoutines.ts)只暴露开关、运行和删除。

最小闭环示例：把“每工作日 09:00 检查资料”改为 10:00，立即看到所用时区和下一次计划时间；试跑结束后进入那一次的结果；若等待审批，直接找到待处理消息。显示“下次计划时间”不代表休眠中的主机会被唤醒，仍需遵守现有调度边界。

这里不仅是表单美化，还需要任务更新、执行身份和消息定位的数据支持。沿用 `src/pi/routines.ts`，不因此引入另一套调度服务，也不自动补跑结果不明的任务。

### 3. 产物：先解决查找与来源，再谈版本系统

现有 [OutputContent](../src/components/agent-preview/outputframe/OutputContent.tsx)产物列表主要呈现当前对话文件名；工作区搜索已有自己的范围，不能当成跨对话成果检索。

建议分两步：先为已有产物补可解释的标题、类型/时间、来源对话和过滤；再评估跨会话索引与真正保存内容的版本。文件后来被覆盖时，“有 revision 字段”不等于仍能打开旧版字节，界面必须区分当前文件和历史快照。

Rakazo 的名称/描述搜索只过滤已加载页，是一个需要避免照搬的限制。RaytoneBot 若先做局部筛选，应明确范围；承诺全量搜索时要由主机覆盖全部匹配记录。

### 4. 运行过程：读结果容易，核对过程也容易

官网示意把主要空间留给结果和待办，电脑画面作为需要时打开的辅助上下文。源码则提供收放工具过程的实际机制。值得学的是这种信息层级，而不是整体更换为深色皮肤或复制尺寸。

RaytoneBot 的工具完成摘要已经具备这个方向。后续只需用长任务核对：是否能快速看出当前在做什么、哪个动作需要我、结束后产物在哪里；展开后是否仍能查到失败和重试。用户上翻阅读或打开旧产物时，不应因新事件反复跳转焦点、切换 Output 页签或展开整段日志。

## 不应照搬的细节

- Rakazo 此快照的搜索异常会清空结果，容易与“没有匹配”混淆；保留 RaytoneBot 已有的失败反馈。
- 工具摘要统一标 Done 不足以表达失败或取消；保留现有终态区别和明细。
- 部分预览操作只在悬停/聚焦时露出；触屏应有可发现的明确入口。
- 多端客户端、整台电脑、共享/私有电脑和外部记忆服务都需要各自的产品与运行条件；这次 UI/UX 借鉴不构成引入它们的理由。

## 建议验证方式

实施时应按功能分别验收，不能用外观相似代替行为完成：

| 场景 | 验收问题 |
| --- | --- |
| 新建研究 Bot | 不阅读引擎文档，能否建立明确职责并开始第一项任务？默认权限和模型是否保持可理解？ |
| 在聊天里改记忆 | 是否直接打开正确 Bot 范围，返回后草稿和阅读位置仍在？ |
| 调整例行任务 | 时区与下次计划时间是否一致，保存失败是否保留草稿，运行记录是否定位准确？ |
| 找回上次报告 | 能否辨认来源和时间，跨会话结果是否完整，当前文件与旧版是否清楚？ |
| 长任务和接管 | 当前步骤、失败与待处理是否可见，展开日志不丢信息，接管/交还的控制权是否明确？ |

本轮仅补调研文档和入口记录。已核对相关代码、官方界面资料和本地引用路径；未修改产品代码，未运行 Rakazo 完整服务、真实模型或部署验收。
