# 09 踩坑记录

按主题分组。每条：现象 → 原因 → 做法。排障时先搜关键词。

## AgentSphere / E2B

- **`404: method not allowed`** → 装了 e2b SDK 2.x → 用 `e2b<2`（实测 1.11.1）。
- **SDK 连到 e2b.dev / 沙箱连不上** → 没设 `E2B_DOMAIN` → 设为 `agentsphere.run`。
- **停服务后 5188 仍被占用** → 后台命令记录的是外层 shell 的 PID → 启动命令用 `exec`，保证 PID 就是 Node 进程。
- **云域名访问被 Vite 拒绝** → Vite 的 Host 检查在插件之前 → 在 `preview.allowedHosts` 里显式写实例域名。
- **很多 `agentsphere-codesphere-*` 模板不可用** → 构建失败的历史残留 → 先 `GET /templates` 查 ready 状态。

## 沙箱持久化

- **timeout 设 7 天被截断/拒绝** → 平台上限 50 小时 → 用 50 h，到期自动暂停。
- **续期返回 204、`endAt` 却不变**（2026-10-05）→ 单次运行窗口从启动（或最近一次恢复）起算最多 50 小时，`set_timeout` 不能延到 `startedAt + 50h` 之后，且不报错；与自动暂停无关（两个临时沙箱对照均可续期） → 先 `POST /sandboxes/{id}/pause`，再 `POST /sandboxes/{id}/resume` 带 `{"timeout": 180000, "autoPause": true}`，窗口从恢复时重算；内存快照保留进程与 Telegram 连接，生命周期设置不变。续期后用 `GET /sandboxes/{id}` 核对 `endAt`。
- **想给现有沙箱开自动暂停** → 生命周期只能在创建时设置 → 新建沙箱再部署。
- **`autoResume: true` 报 400** → 该字段是对象 → `{"autoPause": true, "autoResume": {"enabled": true}}`。
- **暂停后访问 URL 得到 502** → 平台代理不唤醒 → 本机 `sandbox.py wake`。
- **沙箱在运行，URL 却 502，日志无报错** → 服务用 SDK `background=True` 启动，挂在 SDK 命令会话上，部署脚本退出后被一起清理 → 用 `setsid nohup … &` 完全脱离后启动（`deploy.py` 已改）。先用 `sandbox.py status` 区分「沙箱暂停」与「进程不在」。

## Claude Code / Codex CLI

- **Claude 子 Agent 的工具全部失败：`Tool permission request failed: AbortError: Stream closed`，连 `echo` 都不行** → 后台子 Agent（`run_in_background`）在主回合 `result` 之后还在跑，而我们在 `result` 时关闭 stdin，它们的权限请求无处可答 → Claude 子进程设 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`，子 Agent 在前台跑完（同一消息里多个仍可并行）。排查：统计对话里 `tool.call.error` 的 message。

- **Claude 在模型服务模式下仍请求本机网关** → `~/.claude/settings.json` 的 `env` 段优先于进程环境变量，`--safe-mode` 不跳过它 → 模型服务模式加 `--setting-sources ""`。
- **本机登录模式 401** → 这台机器的「本机登录」就是继承的 `ANTHROPIC_BASE_URL/AUTH_TOKEN` → 本机登录模式不要删除 `ANTHROPIC_*`，只删父会话标记（`CLAUDECODE`、`CLAUDE_CODE_SESSION_ID` 等）。
- **「请求权限」下 `pwd` 没弹审批** → Claude 自动放行它判定为只读的命令 → 通过 `--settings` 给 Bash/Edit/Write 加 `ask` 规则。
- **以为 Codex 不能用 DeepSeek（错误结论）** → Codex 确实只支持 Responses API，但 DeepSeek 原生提供 `/v1/responses` → 用 `-c model_providers.<id>.{base_url,env_key,wire_api="responses"}` 即可，无需登录。下结论前先实测接口，别只凭文档推断。
- **`CODEX_HOME` 指向不存在的目录** → Codex 直接退出 → 先创建目录。
- **只有 Chat Completions 的服务商要跑 Codex** → 需要协议转换网关（如 magpie 的 `serve`），见根目录 `issue.md`。
- **Codex 的顶层 `error` 事件** → 可能只是重连提示 → 只有 `turn.failed` 判失败。
- **改了 `src/pi` 服务端代码不生效** → Vite 不热更新插件里的 Node 模块 → 重启 `npm run dev`。
- **请求总落到 Pi** → HTTP 处理函数逐字段构造输入，新字段要显式转发（曾漏掉 `agentPreset`）。
- **`node --test` 跑不了某些模块** → Node 原生剥类型不支持参数属性，也要求相对 import 带扩展名；可测模块保持只依赖 `.ts` 显式路径。

## 权限

- **独立 Agent UID 仍能通过 Pi 文件工具读 bot 文件** → 只降权 bash/CLI，而 read/write/edit 仍在 bot 进程内 → 7 个 Pi 工具都复用定义、在降权 worker 执行；用实际 read/write/bash UID 探针验收。
- **目录路径检查通过后上传仍可能被改到别处** → 检查与写入之间父目录被换成链接；提前 realpath 整个 role 目录还会把链接目标误当工作区根 → Linux 保留配置路径，以逐级 O_NOFOLLOW 目录 fd 锚定遍历和写入；scope 根链接也拒绝。
- **AgentSphere 的 iptables owner / nft inet 规则无法安装** → 模板内核缺少对应扩展 → 使用独立 nft ip 与 ip6 表的 meta skuid/drop；原子安装并读取规则核对，失败时拒绝启动隔离任务，不能只设 HTTP_PROXY。
- **CONNECT 域名白名单仍可能连接同 CDN 上其他域名** → TLS SNI 与 CONNECT host 可以不同 → 建立上游连接前校验 ClientHello SNI，并固定经过校验的公网 IP；这不等于 TLS 内容审计，不能宣称 DLP。
- **外部脚本失败时泄露上游正文或跨域转发 key** → 默认 urllib 重定向保留认证头、通用 fail 打印响应体 → 凭据请求禁重定向，错误仅保留状态码；部署配置、访问密码与任务 ledger 统一在选定 state-dir 下。

- **`git -C <应用目录> checkout` / `npm --prefix <应用目录> run build` 绕过审批** → 写命令规则只匹配紧跟可执行文件的子命令 → 识别全局选项后的写子命令，并覆盖 auto、allow-all 和已记住「始终允许」的情况。
- **`git log --grep=reset` 或路径中的 `x` 误触写审批** → 跨任意参数搜索写关键词 → 跳过全局选项及其值，仅匹配子命令；未知全局选项保守处理。
- **任务里一直弹审批，点「始终允许」也没用** → 读取应用自身代码被归为「受保护」，受保护调用在任何模式都问且不受「始终允许」影响；bash 只要命令里出现该路径就算 → 应用目录改为只读路径（ADR-013）：读放行、写仍问。排查方法：拉 `GET /conversations/:id`，统计 `tool.call.awaiting_approval` 的参数。
- **审批卡片参数为空** → Claude 的参数按片段流入，拼到一半时卡片取了旧值 → `requestApproval(id, args)` 用 harness 权限请求里的完整参数。

## 并行运行

- **输出超限同时收到 SDK 完成时出现成功/重复终态** → 停止回调在微任务里，而 SDK 能同步完成 → 持久化层以限额失败优先，终态只记录一次；回归必须在同一个调用栈发超量 delta 与 agent_settled。
- **工具已隔离，Pi 上下文仍能读到 bot 文件** → 资源加载器以 bot UID 跟随 Agent 可写目录中的 AGENTS/SYSTEM/skills 等符号链接 → 沙箱关闭自动资源发现，固定工作区说明从代码生成；额外文件通过隔离工具读取。符号链接 sentinel 回归先复现泄露再验证修复。
- **Agent 直连 DNS 被拦仍可解析公网域名** → 经 Unix socket 调用 systemd-resolved，发包者变成系统服务 UID → 对 Agent 单独设置 `/run/dbus`、`/run/systemd` 目录 ACL，保留其他系统用户权限；启动前校验 ACL。只测试 UDP/TCP 直连不足以证明没有 DNS 旁路。
- **隔离后 Pi find / Claude 模型请求失败** → 模板 fd 8.3.1 不支持 SDK 使用的 `--no-require-git`；Claude 原生 Messages 请求附带 `?beta=true` → 部署安装兼容的固定官方 fd 版本，代理只放行该精确 Anthropic query。验证要运行真实工具和 CLI，不能只测可执行文件存在或手工拼请求。
- **点停止后仍发起模型请求** → 临时模型 lease/模型设置是异步的，abort 先于真正 prompt → Pi bridge 在开始 prompt 前核对停止代次；停止发生在准备阶段也不能开启新轮次。

- **审批批准到别的对话** → 审批 ID 用毫秒时间戳，同一毫秒的两轮相同；且按顺序找第一个匹配的闸门 → ID 用 `randomUUID()`，前端带 `conversationId` 限定范围。
- **重复提交把原任务停了** → 断线取消在抢到运行槽前就绑定，被拒的请求关闭时也会 abort → 用请求自己的 `AbortSignal`，`runPrompt` 抢到槽后才监听。
- **停止后运行槽一直被占** → `signal` 已取消时再挂 abort 监听不会触发，`wait()` 永远挂起 → 进入等待前先检查 `signal.aborted`。
- **Pi 自动重试或压缩上下文后成功仍显示失败** → `message_end(error)` 先于恢复到达；压缩恢复未必发 `auto_retry_start` → 先暂存错误，重试开始或成功的 `message_end` 时清除，结束时再判定；压缩后仍失败时保留错误。
- **打开历史后马上续问，页面丢消息** → 历史响应与新一轮各自整份替换会话 → 共享一次历史加载，续问先等它；历史只填充仍为空的会话。
- **刷新后打开运行中对话，新进度/审批被旧历史覆盖** → 重接与选中对话各发一次历史请求 → 两者共享加载，屏幕更新拒绝比当前事件更短的快照。
- **点停止后页面已停，服务端还在执行；或重接流再次断开后停止更新** → 本地连接状态被当成任务状态 → 等待停止接口成功才取消订阅；网络失败保持运行并退避重接；明确的 prompt HTTP 拒绝仍显示错误，不被重接吞掉。
- **并发拒绝/请求未到达时消息静默消失** → `/prompt` 已发 200 后才检查运行槽，普通流错误被重接吞掉；mock 409 没覆盖真实路由 → 用真实 HTTP 测试拒绝流中的用户消息与终态；用 `requestId` 核对本次提交，不能用「会话存在」代替。
- **主机永久不可达仍无限运行** → 重连没有次数上限，等待响应没有超时 → 连续 5 次失败后显示状态未确认的错误；对握手、历史请求和缺失心跳设超时，正常心跳不限制任务时长；旧订阅失去控制器所有权后取消待提交帧。
- **重接时最后几段回答丢失** → 读历史与订阅 `/live` 之间任务结束，409 被当作无需处理 → 再读保存历史，只补游标之后的事件。
- **重启后首个 token 前的任务仍悬空** → 没有打开的文本/工具块被误判为任务已结束 → 以 run 终态判断；即使没有开放块，也为未完成的 run 补取消终态。

## 构建与体积

- **按库拆 chunk 后首屏反而变大** → `codeSplitting.groups` 的 `test` 写成宽泛的 `/node_modules/` 会把按需加载的库（mermaid、cytoscape）并进首屏共享 chunk → 只为首屏本来就加载的库建组，并对比「入口 + preload」总量（拆分前后应相等）。React 系（react、react-dom、scheduler）必须同组，分开可能出现两份 React（`useMemo` of null）。
- **改成 `lazy()` 后 chunk 仍在首屏** → 还有别处对该模块的值引用（例如从 `OutputFrame` 取 `normalizeOutputPanelRequest`）→ 改为从其源文件引入；纯 `import type` 不受影响。

## 界面

- **设置弹层看不见** → 输入栏 `.composer-tools` 裁切溢出，欢迎页上弹层还会超出视口顶部 → 用 Radix Popover 渲染到 body 并开启碰撞处理。
- **复制控件只有图标，或点击失败却无提示** → 消息按钮没有 onClick/原文，其他入口忽略 Clipboard Promise 拒绝 → 把对应消息原文传到既有控件，共用等待浏览器写入、失败反馈及卸载清理。不要从渲染后 DOM 收集文本，否则会丢 Markdown 或混入其他消息/按钮；验收需读回实际剪贴板，并模拟拒绝与 API 不存在。

## 浏览器验收

- **自动化浏览器报 `ERR_BLOCKED_BY_CLIENT`**（Codex 内置浏览器、受控 Chrome）→ 客户端拦截，不是服务问题 → 用本机普通浏览器手动验收；不要为此关闭鉴权或改服务器。
- **双击 `index.html` 白屏** → `file://` 禁止 ES module → 始终用 `npm run dev` / `npm run preview`。

## 事件与界面

- **界面上缺某个状态** → 事件没发对，而不是缺组件 → 查 `piAdapter.ts` 与 `admissionReport.ts`。

- **工具已完成还在“正在执行”，失败却显示“已修改”** → adapter/view model 已有正确终态，卡片却按旧标题判断活动状态，且文件行隐藏了真实错误 → 标题、动画、文件行统一读工具 status；失败/取消展示输入与回执，只有真实成功才能用完成措辞。原生 read/write/edit 与 CLI 参数需走已有工具分类，不能只测 fixture 的 read_file/edit_file。能力声明场景空白则还要查 slot 是否在项目配置中禁用。
- **结构化表单产物显示 `[object Object]`** → vendored view model 对 `artifact.delta.payload.delta` 调 `String()`，对象应走其 `data` 字段 → 在实际 `useAgentUXReplay` 入口转换 JSON delta，保留存储事件原样，并以真实 view model 验证。`eventNormalizer` 仅用于 admission report，单改它不会修复产品回放；JSON 可读不等于表单交互已接通。
- **产物下载指向不存在的文件** → 把标题/副标题当作工作区路径 → 只以明确文件引用生成下载 URL；内存内容使用可回收的 Blob URL，缺失内容保留空态，不合成演示文件。
- **媒体看起来能预览却没有真实内容** → 导出壳按文件名选固定图片，播放条只有图标与装饰 → 复用已鉴权下载接口取实际文件，使用原生 img/audio/video；缺失、损坏和超限都显示真实失败。需要整份读取的图片/文本/PDF 同时检查 Content-Length 与累计字节，取消旧请求并回收 Blob；大音视频使用下述原生流式路径。
- **`?devtools=1` 里能看到但真实运行看不到** → 差异在适配层，fixture 是理想事件。

## Pi 运行时

- **侧栏节点少但主机内存仍随历史增长** → 列表调用正文读取器把每份 JSON 留进无限 Map → 先测量常驻堆，再将摘要和有界正文缓存分开。未 flush 的流式事件必须单独保留；否则打开旧会话或全文搜索会把尚未落盘的增量淘汰。验收要在真实流暂停时扫描历史、刷新接回再结束，并核对磁盘序号与内容，不能只测静态列表数量。可复跑 `node --expose-gc scripts/check-history-memory.mjs`。
- **刷新后会话没了** → 曾是 `SessionManager.inMemory` + 前端 React state，T1.3/T1.4 已修 → 若再出现，检查 `RAYTONEBOT_DATA_DIR`（默认 `~/.raytonebot/data`）是否可写。
- **云端没有可用模型** → 沙箱 `~/.raytonebot/env` 里没有 `DEEPSEEK_API_KEY` → 部署时在本机环境设置该变量再运行 `deploy.py`。
- **Agent 写的 `.pi/extensions/*.ts` 在 bot 进程里执行** → `createAgentSession` 不传 `resourceLoader` 时用 Pi 默认加载器：SDK 模式默认信任项目，会加载 cwd 与全局目录的扩展，并自动安装 `settings.json` 里的 packages → 用 `createHostResources()`（`noExtensions` + `projectTrusted: false`），见 `piResources.test.ts`。
- **Pi 拒绝请求 403** → `requestOrigin.ts` 只放行 loopback；云端靠 `cloud-preview.mjs` 鉴权后把 Host/Origin 标准化为 `127.0.0.1:5188`。不要用 `vite --host 0.0.0.0` 直接暴露。

### Pi 主动停止也可能先发模型错误（2026-10-03）

真实 SDK 的 `abort()` 尚未 resolve 时，可以依次发 `message_end(stopReason=error, errorMessage="This operation was aborted")`、`agent_settled`。只在 await abort 后 `finish(cancelled)` 会被已发出的 run.error 抢先终结。Host 根据该轮 stopRequested 把 SDK 终止映射为取消，并在 prompt 抛错路径同样兜底；回归测试必须模拟 abort 期间同步发事件，不能只让 promise 正常结束。

### 文件面板重挂载会清空 Composer 本地草稿（2026-10-04）

`rightPanelVisible` 在 soloStack 与 RightPanelLayout 之间切换，Composer 会重挂载；附件加入真实上传链路后，这会丢失待发 File。文字与附件应由 AgentApp 按 conversationId 持有，通过现有 ShellExtras 传入；组件单独使用时保留本地状态。异步接受回调绑定原会话，并只清理已提交的附件 ID/未改写的文字。浏览器实际验证面板开关、切换会话、缺少 key 的失败状态。

同一重挂载也会丢失聊天阅读位置。2026-10-04 实测第 13 轮开面板跳回第 20 轮；只保存 scrollTop 又会因文本重新换行而定位错误。当前由 shell 保存首个可见行及相对偏移，滚动 hook 负责恢复；会话/用户消息变化仍重置到底部。用真实长历史在修复前复现，再核对开关面板后的行索引与偏移；不要只验一屏内的短场景。

同一边界也影响权限模式和思考预算：云端默认 auto 时，用户手选 request 后打开产物会重置为 auto，下一轮可能不再询问。把选项交给 shell 按会话持有，复用 ShellExtras；除检查控件文案外，还要在面板重建后真实提交并核对请求与审批。内存中保留不等于跨刷新持久化，文档须明确区分。

### 草稿恢复必须区分草稿、请求与已提交历史（2026-10-04）

- 会话权限/预算与待发送内容共存时，接收回执只能清内容；纯选项仍需保存版本以防旧标签覆盖，但不能成为可发送消息或把已完成历史当成待恢复草稿抢走导航。未手选字段保留默认值继承；损坏权限恢复时不能扩大授权。
- 侧栏只挂载可见行后，新增草稿会改变旧行位置，不能再依赖浏览器对完整 DOM 的滚动锚定。实测新增一条使原行从 1.5px 跳到 38.5px；应按会话键修正 scrollTop，保留行内偏移，顶部则继续显示新记录。键盘导航必须按完整列表索引，不能只在当前挂载的行中循环。
- File 不能用 JSON/localStorage 伪装持久化；IndexedDB 保留真实字节，验收要在刷新后实际上传并比对。
- 提交后的刷新不能只恢复编辑框：先用请求 id 核对服务端记录，接受后仅清掉提交快照中的内容。前端合成的错误也带 runId，不能用它证明已被主机接受；只有主机历史/流中的确认有效。
- 两个标签页的草稿版本可能不同。写入和清空均需在同一事务比较版本，不能让旧页面覆盖新草稿；保存状态必须按会话记录，不能用另一个会话的保存成功掩盖失败。
- 浏览器回归要检查场景实际内容。自动恢复历史后，原事件选择器只改变 streamId，piEvents 仍覆盖展示；明确选中 fixture 时使用它的事件源，回到会话再恢复实时源。菜单名字变了不代表场景经过验收。

### 计划与产物更新必须跟随身份和所属轮次（2026-10-04）

- 完整计划快照不能反复追加为 text delta；用 JSON data 替换快照，保留单个 artifact id，否则步骤会重复。多轮都叫 Plan.md 时不能按标题合并。
- Claude 2.1.287 新任务工具对部分模型需要显式开启 TODO_TOOLS/TASKS；回执的 `tool_use_result` 在 stdout 行的顶层，不在 `message.content`。创建用回执的 task id，更新需检查 `success` 和 `updatedFields`；未知任务可返回 `success:false` 而没有 `is_error`，不能据请求参数宣告完成。原生任务还存于 `.claude/tasks`，只备份会话目录会丢任务。真实 CLI 配合本机受控模型服务可验证这些边界，不需要付费请求。
- 点击产物时复制内容会让打开的面板落后于实时卡片；按 artifact id 从当前 view model 更新同一标签，同时覆盖标题、副标题和正文。
- 计划产物“可阅读”不等于所有步骤完成；停止、失败、重启的终态应按 runId 关联，仍保留最后报告的未完成步骤。
- 展开的 Markdown 是 grid 容器；不给 `align-content: start` 会把很短的段落均匀拉满手机弹层。检查截图，不能只确认文字存在于 DOM。

### 历史落盘不等于用户能找回历史（2026-10-04）

- 移除服务端 200 条清理后，客户端共用更新函数仍截成 100 条，流式提交就会让旧记录从侧栏消失。验收需在超过上限的数据量下更新一轮，再搜索另一条旧记录。
- 请求失败不是空历史；错误反馈只进入显示层，不能追加到真实事件数组并推进重接游标。404 需区分已保存历史缺失与未被主机接受的本地草稿，恢复成功后清除旧错误。
- 搜索弹层放在主内容的 portal root 会被手机侧栏抽屉盖住；DOM 存在不代表可操作。用覆盖整页框架的既有弹层，并实测截图、Tab / Shift+Tab、Esc 和选择后的焦点返回。

### 取消成功也可能被同一次点击重新提交（2026-10-04）

- Composer 同一按钮在运行中为 `type=button`，空闲时为 `type=submit`。取消上传会快速使 fetch 抛错、清除运行态；浏览器执行点击默认动作时，按钮可能已变成 submit，于是又上传一次。临时日志实测顺序为 abort→catch→第二次 upload，不是 AbortController 失效。
- 停止的 click handler 先 `preventDefault()` 再取消；复验必须等待请求确实进入上传阶段，点击停止后确认没有第二次请求，再刷新确认草稿和附件仍在。只在配置阶段马上停止会漏掉该竞态。
- PDF 不能走 `Blob.text()`；渲染分类、MIME 和文件头校验必须一致。浏览器 `pdfViewerEnabled` 为真仍不保证嵌入成功，截图检查实际页内容，下载保底与目标客户端兼容性分别记录。

### SDK 更新要核对实际安装树和事件语义（2026-10-04）

- 发布包的 `npm-shrinkwrap.json` 可以固定间接依赖，使根项目的 `overrides` 不生效；Pi 0.84.4 在干净目录也复现了旧版本。确认 `npm ls`、lockfile 和干净 `npm ci`，不能只看配置里写了新版本。升级范围与依据见 [04](04-dependency-exit.md)，不能直接 `audit fix --force`。
- 用本机受控模型协议驱动真正的 SDK，可以验证工具列表、审批时序、副作用和原生上下文；伪造 bridge 无法发现 SDK 的事件顺序变化。计数“整轮取消成功”也不够，工具可能先收到 error 而显示失败；停止请求后的 SDK 工具错误应等最终取消收尾，普通执行错误仍保留。

### 大媒体与失败重试要验证实际传输（2026-10-04）

- 把所有媒体先读成 Blob 会让可原生播放的视频撞上 20 MiB 上限。复用受保护的下载 URL 和单段 Range，播放器负责按需读取；文件路径仍由原有校验器处理，用同一描述符流出，不能为 seek 重新打开路径。
- 移除播放器 DOM 不等于取消传输。清理时 pause、移除 src、load；限速下播放再关闭，核对浏览器 Media 请求确实 cancelled，而不只检查元素消失。
- 损坏文件修复后，浏览器可能复用同一 URL 的失败缓存，点击重试没有新请求。下载响应 no-store，预览重试使用临时参数；以实际替换文件、缺失后恢复和重新显示首帧验收，临时地址不持久化。

### 用户问题不能复用权限批准（2026-10-04）

- Claude 的 can_use_tool 也承载 AskUserQuestion；直接走普通 permission gate 会在 allow-all 下无回答继续。先辨别交互语义，问题必须独立等实际答案，不记 always-allow。
- 工具出现在模型列表不证明可用：Codex 默认模式仍会拒绝 request_user_input。用实际 CLI 和本机模型协议完成返回链路，核对模型真正收到的答案，并复验原审批副作用。
- 验证真实 replay 入口：eventNormalizer 并不自动作用于 agent-shell 的 Pi 事件。显示投影只能过滤呈现副本，不能改变存储事件或重接游标。问题和答案用现有消息，避免展示原始 JSON 或 CLI 内部提示词。
- 用户问题长度变化大；手机验收既要看短问题，也要实际滚动长问题到提交/跳过区域。DOM 中有按钮不等于屏幕内可点击。
- 切题会卸载按 question id 区分的输入框，Enter 后可能把键盘焦点丢到 body；在用户前进/后退后的布局更新中聚焦新问题标题，再用 Tab 进入选项。仅检查点击成功不能覆盖这条路径。
- 组件已经换成停止图标，主题的 `::after` 仍可能强制画发送箭头；同时核对可访问名称与实际截图，主题图标必须按真实按钮状态区分。


### 文件保存成功与界面接收确认要同一边界（2026-10-04）

- 只有 ENOENT 能表示记录不存在。JSON 损坏、读权限失败或结构不符必须报错，不能在下一次 begin 时覆盖原文件；一个坏文件不应藏掉全部正常历史。
- 原子 rename 不会自动保证缓存正确。写成功后才更新元数据缓存；事件批次写失败要清掉未提交缓存，否则后续 GET 仍可能读到磁盘没有的成功终态。
- 用户消息、终态和交互等待须先写盘，再发接受/完成回执。普通流式增量可批量写，但不能以“HTTP 已返回 200”或“文字已出现”推断持久化成功。
- 存储失败的错误本身也可能保存不了。当前连接要收到明确错误，刷新通过只读的缺失终态提示说明边界；不能让已执行任务变成 prompt_rejected，也不能自动重发。
- 重启补中断标记仍是一次写入，也会失败。保留可读历史与故障提示，不让单条会话的补写失败阻止整个主机启动。用真实文件写失败、冷控制器和浏览器刷新验证，不能只模拟 fetch 返回码。

### 原生上下文不是聊天记录的显示副本（2026-10-04）

- CLI 的 resume 找不到记录时不能自动 start 新 session；Pi 的 `continueRecent` 也会在无文件时新建。页面仍显示旧聊天容易掩盖模型上下文已丢失，必须独立验证模型真正收到的历史。
- Pi 在 SDK preflight 的 started 回调保存原生 id，早于模型/工具动作；null 表示尚未接受，缺省表示旧格式。绑定写失败必须阻止执行；不能在模型/key 配置失败时制造不可恢复的假绑定。
- SDK 的 JSONL 恢复解析器可能跳过损坏行。恢复前校验文件，不能因损坏而换用另一份历史；旧会话迁移、新建、真实重启、缓存期间丢文件应分别验证。读取校验仍不是跨文件事务或完整树结构验证。
- 原生 fork 只切模型上下文，不回滚文件。需要保存每轮原生定位信息，再接编辑／重新生成；重复发送旧文本不是等价实现。
- 分支验收须在冷重启后的子会话续问再次比较来源文件；仅验证首次 fork 不能覆盖错误的恢复绑定。浏览器选择原会话会触发配置同步，Pi 可能追加 model_change；应区分这次显式选择与子会话写入，不能只用最终文件哈希归因。只有配置、没有用户或 assistant 消息的 Pi 前缀应在分支写入前拒绝，避免先绑定一个现有恢复校验无法读取的子文件。

- 搜索分支继承消息时，旧、新会话可有相同 textId；不能用“DOM 找到消息”证明目标历史已经渲染。useAgentUXReplay 的 effect 回放会晚一轮，已实际造成定位 nonce 被旧 DOM 消费；本项目改用 SDK 原有校验/回放/视图函数同步派生。回归要从已加载来源打开尚未加载的分支，并核对消息集合、定位与草稿。
- 搜索弹层的 max-height 不保证网格子项会收缩；多条片段撑大 auto 行时，scrollIntoView 连 overflow:hidden 的父层也会滚，搜索框随之消失。固定为 auto minmax(0, 1fr)，并用手机末项键盘导航验证只有结果列表滚动。
- 消息操作不能靠回复文本或原生 messageId 猜轮次：适配器可能每轮都从 m1 开始，同样的回答也可能重复。显示层复用按轮次区分的 textId，与实际事件关联；不重写已保存事件。用户消息另经 UserPromptBubble 包装，也须传定位信息，单测只看按钮存在不能证明可点击。
- 从历史编辑带回的附件是服务端引用，不能伪造 File 或下载后无谓重传。引用随草稿保存，发送前检查可读性并保留失败草稿；服务端仍做最终校验。异步分支完成时要检查用户是否还在来源会话，避免切走后被拉回或自动触发任务。

### 搜索应找到可打开的消息（2026-10-04）

- 正文搜索先按 runId/textId 合并增量；不能逐个 delta 搜索，也不能拼接不同消息制造匹配。用户查询按字面量处理，工具参数、思考和原生文件不是可见正文。
- 旧响应、读取失败、部分损坏和真实无结果是不同状态。取消查询不改变当前会话；服务端新发现的记录须先进入会话状态，点击才能打开，活跃记录须接回订阅而非重发。
- 搜索定位复用原消息 textId；一次定位的标记放进已有滚动记忆，避免布局重挂载后反复抢走用户阅读位置。查询片段和能打开完整记录应分别做浏览器验收。

### 搜索可见行与焦点（2026-10-04）

- 虚拟化后不能从当前 DOM 按钮集合推算上下项；按完整结果及会话/消息联合标识导航，再挂载并聚焦。滚轮离开当前焦点时只额外保留该行，避免渲染焦点与视口之间的全部结果。
- 片段行高随窗口宽度变化；清空测量缓存之前必须保存可见消息与相对位置。仅保留 scrollTop 已实际导致 390px/480px 切换时阅读位置跳走。

### 原生任务的读取接口不是同一份快照（2026-10-04）

- Claude 2.1.287 实测 TaskGet 不返回 owner，TaskList 返回 owner 但会过滤已完成的 blockedBy；不能用相同的对象替换规则处理两种回执，也不能将产品展示当作完整依赖图。
- TaskUpdate 对不存在的依赖 id 可返回 success 并忽略该 id；成功只证明被报告字段发生更新，不证明每个请求 id 被接收。已有任务可按确认回执投影，无法确认的依赖须标待核对，随后用 TaskGet/List 的实际数据更新。自引用和删除前置任务的行为也应按原生回执验收，不自行推断执行完成。

### 待答问题恢复不等于回答草稿恢复（2026-10-04）

- 主机保存了问题，刷新仍可能把浏览器选项、自由文字和题目进度清空；验收要在第二题实际填写后刷新并重选会话，再核对前后两题和原生引擎收到的完整答案。
- 本标签页草稿以 conversationId/requestId 隔离，仅保存输入数据；不能恢复 pending/done 或自动调用回答接口。提交失败保留草稿，迟到确认只删除匹配问题，存储不可用不能禁用手动回答。sessionStorage 不等于跨设备同步或服务端持久任务。

### 审批回执必须绑定具体请求（2026-10-04）

- 只用 toolCallId 记住已关闭审批，会把 A 的迟到回执应用到 B 的同 id 工具；真实 Pi SDK 双会话已复现。关闭标识和组件 key 都应包含会话及 awaiting 事件身份，异步回执还须核对当前请求。
- HTTP 失败后保持卡片并不足够：吞掉错误会让用户以为按钮没反应；无超时会一直锁住。两种表面复用 pending/failed 状态和同步点击锁，15 秒后恢复手动重试，明确“未确认送达”，不能断言主机没有执行或自动重发。
- 同一个原生工具 id 也可能跨轮复用。验证既要检查审批请求归属，也要检查旧工具卡是否被新状态覆盖；这两者是不同的事件映射边界。
- 渲染器把整个会话的工具和产物分别放在一个 id Map 中，原生 id 不能直接用作跨轮显示身份；文件产物也会因此串内容。显示层按 runId/类型/原生 id 投影，审批再从真实事件还原原生 id，避免改写磁盘和破坏 gate。只修卡片仍挡不住迟到 HTTP 批准新轮同 id 工具，主机须同时校验请求携带的 runId。

### 卡片关闭后的焦点属于用户当前操作（2026-10-04）

- 提交时禁用控件和最终卸载卡片都可能使焦点落到 BODY；切题标题聚焦不能覆盖最后一题。跟踪实际聚焦过的控件，失败后原位恢复，卸载后再检查当前会话及 DOM 焦点，不能让迟到回执打断另一个会话或搜索输入。
- 停止按钮会变成禁用的发送按钮，应在用户显式操作时交回 Composer；不要在异步停止完成时无条件 focus。真实浏览器分别验证成功、失败、停止与切走，单测的元素替身不能证明浏览器禁用行为。

### 停止失败需要可见回执（2026-10-04）

- 失败后保留连接只是执行语义正确，吞掉异常仍会让停止按钮看起来失效。现有状态行须显示未确认，允许手动重试；不能把 HTTP 失败当作已停止，也不能清空草稿。状态绑定请求发出时的本地订阅，不能让迟到响应影响另一会话或新轮。
- 单测中的失败 fetch 不能证明网络恢复。用真实 SDK 任务与 HTTP 连接中断，分别核对客户端重试次数、主机 activeRuns、恢复后的原事件和模型请求计数；迟到响应与迟到请求是两个不同边界，后者还需服务端轮次校验。
- 停止须绑定发起时的 runId；仅检查本地 AbortController 不能阻止旧 HTTP 请求到达主机后取消下一轮。恢复连接应读取临时 activeRunId，主机按运行槽同步校验，内部延迟停止回调也要捕获相同身份；缺少身份不能静默退回按会话停止。分别验证延迟请求、刷新后的新轮停止及引擎尚未初始化的已占槽停止。

### 已缓存历史仍需要重新连接（2026-10-04）

- “从侧栏重新选择以重试”的文案必须对应真实读取路径；只在 stored 且 events 为空时加载，会让重连耗尽后的已加载会话永远停在旧状态。重选应复用共享读取/订阅，已在订阅时直接复用，避免并发发送或重复连接。
- 客户端连接失败不等于服务端轮次失败。错误和未确认消息只在显示层投影，不能追加到服务端事件数组并推进 after 游标；成功读取权威历史后清除。真实浏览器同时验运行仍在继续、离线期间已完成、迟到读取切换会话与未送达草稿，不能只验证刷新页面成功。

### 设置恢复必须到达实际请求（2026-10-04）

- 表单显示新地址不等于刷新后仍使用它；从静态项目执行初始 configure 会绕过已恢复设置。验收同时核对刷新后的控件、主机配置和真实 SDK 请求路径，不能只断言 JSON 往返。
- 保存用户修改的字段，避免把所有部署默认值永久冻结；会话 key 不进入偏好记录。模拟浏览器读取/写入失败时，须看到失败提示且之前的有效值仍可恢复；加载默认值不能触发覆盖保存。

### 代码产物不是待提取的 Markdown 消息（2026-10-04）

- 源文件注释也能包含 Markdown 围栏；用正则提取第一个围栏会把完整 JavaScript 截为注释片段，语言也被误判。代码产物直接展示/复制其原文，不 trim；语言来自文件身份。助手消息中的代码块属于另一条渲染链路。
- 原生 edit 回执已经给出差异，不可再拼造文件头、加号或“之前的实现”。真实文件、持久事件、默认预览、显式打开与剪贴板应分别核对；单测不能替代这些入口的实际观察。

### HTML 预览要贯通父级高度（2026-10-04）

- iframe 固定 280px 会在桌面右栏和手机展开弹层留下大片空白。修复须同时让面板、内容区、产物项分配剩余高度，并允许内容区收缩；iframe 内部负责文档滚动。只对包含 HTML iframe 的分支生效，避免拉伸 Markdown、代码等产物。验收应覆盖默认/显式打开、多标签、展开、窄屏及长页面末尾，不能仅确认 iframe 存在。

### 判断“来自 IM”看本轮来源，不看会话 id（2026-10-05）

- `connect_channel` 曾按会话 id 前缀 `im-` 拒绝显示安全卡片；Telegram 建立的会话在网页里继续时，用户在网页提问也只得到 `open_in_browser`。来源随每轮变化，由 IM 桥接在 `runPrompt` 时标记 `fromChannel`。
- 会话重置、配置与启动一轮须按会话排队：等待中的操作醒来后要重新检查运行状态，且检查与登记之间不能有 await；重置失败要让排在其后的任务失败，不能用 `.catch(() => undefined)` 吞掉。

### 群聊复用子执行，不代表继承了父轮保障（2026-10-06）

- 父轮也需要持久请求身份、停止/审批身份、订阅游标与唯一终态。只调用子会话 `runPrompt` 会漏掉这些规则；错误改写成文字也不能替代错误终态。并行失败要先停止并等待所有子轮，再释放父轮槽。运行中重置不能删除父轮的去重回执。
- 元数据必须先于成功终态写入；终态写盘失败由共享 recorder 报告 `history_save_failed`，不能再被 HTTP 当成未接受的 `prompt_rejected`，否则客户端可能重复提交已经执行过的任务。用真实临时文件存储与受控引擎分别验证完成、重启、断线、等待交互和持续写入失败。
- 打开历史不等于接收消息：首次群元数据失败、尚未保存用户消息时应拒绝并允许原请求重试。订阅回调与成功后的标题查询也能抛错，必须隔离；收尾兜底等 recorder 完成后再广播，否则写入与 flush 同时失败会发两个错误终态。成员错误是否发生不能用错误文案的真假判断，空字符串也必须是失败。
- 并发名额预检有竞争：唤醒只是重试检查的信号，检查身份/容量与占槽之间不能 await。群成员等待不占执行名额、不写子轮回执；取消与 dispose 要解除等待，不能在其他任务退出后悄悄启动。
- 验证写盘失败后的缓存状态，要让真实 `writeFileSync` / `renameSync` 失败，或保留等价的失效语义。直接将 `store.flush` 替换成抛错会绕过 `write` 的清缓存路径，制造生产实现没有的“未接收却被去重”结果；测试桩失败与真实 I/O 失败应分别记录。

### 无凭据模型状态不是普通的已选模型（2026-10-06）

- Pi SDK 的无模型状态是 `unknown/unknown` 对象，不能只按真值判断后在重置时恢复。跳过精确占位值，保留真实配置的模型与思考预算；不通过换默认模型掩盖未配置状态。
- 宿主环境里的模型凭据会令 SDK 自动选出可用模型，隐藏此分支。回归使用干净子进程和临时 Pi 目录，至少覆盖未配置重置、配置后的重置，避免测试结果依赖开发者 shell。
