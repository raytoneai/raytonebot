# 07 架构决策记录（ADR）

格式：编号、日期、状态（已采纳 / 待定 / 已废弃）、决定、理由、何时重新评估。新决定追加在末尾，不改旧条目，废弃时标状态并指向替代条目。

---

### ADR-001 保留 AgentCanvas 导出的 UI，作为自有分叉

- 2026-10-03 · 已采纳
- 决定：现有 React 组件、AgentUX 渲染管线保留并视为自有代码，不再从 AgentCanvas 上游同步。
- 理由：组件已覆盖 Agent 的全部状态（流式、思考、工具、审批、产物、错误、中断），重写没有收益；跟随上游会限制修改。
- 重新评估：需要的交互无法通过事件映射或修现有组件实现时。

### ADR-002 执行运行时使用 Pi，不引入 OpenAgentCore / openbot / CopilotKit

- 2026-10-03 · 已采纳
- 决定：Agent 循环与工具执行使用 `@earendil-works/pi-coding-agent`（MIT），运行在同源 Node 进程内。
- 理由：已接通提交、停止、新会话、模型配置、执行前审批。OpenAgentCore 需要 Go 服务 + PostgreSQL + daemon，其 E2B helper 依赖 SDK 2.x 与 AgentSphere 不兼容，且其原生 Harness 为无人值守执行，不能保留“修改前审批”。openbot 为非商业许可。CopilotKit 模板依赖 Intelligence 平台。详见 `docs/openagentcore-assessment.md`、`docs/nightly-openbot-assessment.md`、`docs/feasibility.md`。
- 重新评估：需要多用户、多引擎、跨实例持久执行或审计时。

### ADR-003 部署在 AgentSphere 沙箱，沙箱视为可丢弃

- 2026-10-03 · 已采纳
- 决定：应用与 Agent 同在一个 AgentSphere 沙箱（`agentmatrix-v1`）中运行；一切状态要能由“部署脚本 + 最近备份”重建。
- 理由：比 VPS/VM 便宜，microVM 隔离 Agent 的 shell；但平台单机、无自愈、有 timeout。
- 重新评估：平台提供持久卷/pause 后，可放宽备份频率。

### ADR-004 会话持久化先用 Pi 自带的文件会话

- 2026-10-03 · 已采纳（T1.3 已实现；实际存储位置见 ADR-012）
- 决定：`SessionManager.inMemory` 改为 `SessionManager.create/open/list`，文件放 `~/.raytonebot/sessions/`；不引入数据库。
- 理由：Pi 0.84.4 已提供，改动集中在 `piHost.ts`；单用户无需查询能力。
- 重新评估：出现任务队列、定时任务、跨会话检索时，考虑 `node:sqlite`（零依赖）。

### ADR-005 单用户 + Basic Auth

- 2026-10-03 · 已采纳
- 决定：公网入口只用 Basic Auth（≥24 字符随机密码）+ 严格 Host/Origin 校验，不做账号系统。
- 理由：首版只有一个用户；Pi 控制器的审批闸门与 cwd 也是单用户设计。
- 重新评估：出现第二个用户之前必须重做身份、会话归属与工作区隔离。

### ADR-006 沙箱内不放 E2B 团队 key

- 2026-10-03 · 已采纳
- 决定：续期、备份、销毁都由本机脚本执行；沙箱内只有访问密码与模型 key。
- 理由：团队 key 可创建任意沙箱，一旦 Agent 工具读到即泄露。
- 后果：本机关机时无法自动续期（见 [06](06-deployment-runbook.md) 续期策略）。

### ADR-009 多引擎：CLI 输出翻译成 Pi 事件

- 决定：Claude Code、Codex 以 CLI 子进程运行，输出翻译为 Pi 会话事件，复用 `piAdapter` 与现有组件；不引入 Claude Agent SDK、OpenAgentCore 或新的事件协议。

### ADR-010 沙箱权限模型

- 2026-10-03 · 已采纳
- 决定：按「受保护 / 对外 / 修改 / 只读」分类；工作区内放开，凭据与应用代码在任何模式下都询问；Agent 子进程剥离密钥；云端默认「替我批准」。参考 openbot 的 workspace/full 访问级别与 OpenMuse 的「对外动作需审批」做法，自行实现。
- 重新评估：完成 S1（独立系统用户）后，受保护路径可改为由文件权限硬拒绝。

### ADR-012 持久化：自动暂停沙箱 + 应用数据落盘 + 本机备份

- 2026-10-03 · 已采纳
- 决定：沙箱以 `autoPause` + `autoResume` 创建，超时只暂停（整机快照）；会话数据存 `~/.raytonebot/data`（Pi 文件会话、对话 JSON、CLI 会话 id），不引入数据库；`sandbox.py backup` 拉回本机。
- 理由：平台单次最长 50 小时、无故障自愈、暂停保留期未知；暂停/恢复实测无损且约 1 秒。
- 限制：平台代理不会在访问时自动唤醒，需本机执行 `wake`（E2B key 不进沙箱，ADR-006）。
- 重新评估：平台支持访问即唤醒或持久卷时。

### ADR-013 应用自身代码改为只读路径

- 2026-10-03 · 已采纳（修订 ADR-010 中「应用代码受保护」）
- 决定：工作区分离时，应用目录（云端 `/home/user/raytonebot`）从受保护路径移到只读路径：读取、搜索、类型检查、跑测试按普通调用处理；写入/编辑，以及看起来会写入的 bash（重定向、`rm/mv/cp`、`sed -i`、`git checkout`、`npm install/build`、`npx`、`sh -c`、`find -delete` 等）仍为受保护，任何模式都询问。
- 理由：一次规划任务审查应用代码时 48 次调用里询问 35 次，「始终允许」对受保护调用无效，任务无法推进。应用目录不含密钥（env 在 `~/.raytonebot`），需要防的是改写 bot 自身代码与重新构建前端。写入判断是启发式，宁可多问；`sh -c` 等无法判断的一律询问。
- 重新评估：完成 S1（Agent 以独立用户运行、应用目录只读挂载）后，写入改由文件权限硬拒绝，可去掉启发式。

### ADR-014 凭据直接拒绝；「始终允许」按 Agent 记住

- 2026-10-03 · 已采纳（修订 ADR-010）
- 决定：(1) 凭据路径与环境变量导出从「受保护（询问）」改为「禁止访问」：任何模式下直接拒绝，不弹卡片，工具结果告知原因。(2) 「始终允许」由按对话改为按 Agent 记住，持久化在 `~/.raytonebot/data/approvals.json`，新建会话不再清空；设置页可按 Agent 重置。
- 理由：参考项目在沙箱内都以边界 + 策略代替逐条审批（Claude Code 沙箱自动放行 Bash、OpenBot 网关 allow/deny、openbot 的 Agent 级授权）；凭据没有正当用途，询问只会养成反射式允许；按对话记住使每个新对话都要重新批准同一工具。
- 重新评估：完成 S1 后凭据改由文件权限硬拒绝；需要授权过期或按工作区区分时。

### ADR-015 单沙箱内使用原生 UID、防火墙与 bot 内模型代理

- 2026-10-04 · 已采纳（本轮工作树，待测试实例与生产部署分别验收）
- 决定：bot 保持 `user`，Agent 工具/CLI 运行于 `raytone-agent`，用 `setpriv --no-new-privs` 禁止提权；应用 root 所有、bot 配置 0700。Pi 的文件工具也移入受限 worker。IPv4/IPv6 出站只允许 bot 的 loopback gateway，模型凭据按轮次替换为可撤销 token；包下载仅开放指定仓库的 HTTPS CONNECT。
- 理由：只清理子进程环境或匹配 shell 文本不能隔离同 UID 的文件与进程；复用 Linux 机制和现有 Node 进程，不引入容器服务、数据库或框架。隔离缺失时沙箱模式拒绝运行，不静默降级。
- Codex 改用原生 `app-server` 的命令与文件审批；默认 `untrusted` + `read-only`，仅批准当前动作，替代整轮写授权。补丁内所有路径（含重命名目标）都进入策略判断。
- 限制：三个角色仍共享一个 Agent UID；CONNECT/SNI 白名单不是内容审计或防泄漏系统。云端只允许已配置的 HTTPS OpenAI-compatible / Anthropic 模型服务，不再使用本机登录。macOS 本机开发保持原有身份，未得到 Linux 硬隔离。

### ADR-016 外部服务负责唤醒与调度，先保留可调用入口

- 2026-10-04 · 用户确认的接入假设（补充 ADR-006、ADR-012）
- 决定：由沙箱外已存在的登录/注册 Web server 持有 E2B 凭据，鉴权并校验 bot 归属后 resume，等待 health 再转入 bot。此轮提供标准库脚本入口，不新增账号服务，不安装 Mac 常驻任务。
- 调度器提供稳定 occurrence id；外部私有磁盘在提交前保存记录，同一 occurrence 不重复提交。不确定结果只读产品历史核对，不能自动重放。外部服务尚未提供，故未激活定时任务或自动备份。
- 限制：本地文件锁只适用于单个外部主机；复制到多实例调度器之前必须迁入其已有共享任务存储。外部备份存储、保留期限、RPO/RTO 与告警待定，完整问题见根目录 `issue.md`。

### ADR-017 草稿由浏览器原生存储恢复，已提交任务仍以主机记录为准

- 2026-10-04 · 已采纳（工作树；补齐刷新丢草稿的缺陷）
- 决定：复用 IndexedDB 的 File 结构化克隆保存真实附件、文字和最小会话元数据；未发送对话复用现有侧栏。无新依赖、服务器、服务端数据库或 UI 组件。
- 理由：OpenMuse 的 composer 在运行中可编辑、停止保留草稿；我们的已有组件也支持这些行为，但刷新会丢失。持久化不应意味着排队执行；刷新只核对本次 request id，不自动重发。
- 接收回执只移除已提交快照中的文字/附件，保留后来编辑或添加的内容；事务内比较版本防止旧标签页覆盖新草稿。恢复期间短暂只读，失败后继续允许编辑并提示未保存。
- 运行选项补充：同一记录保存用户手选权限/预算，接收回执不删除选项；未手选字段继续使用设置／主机默认。纯选项不构成消息；已完成历史的选项恢复不抢导航，空草稿选择可独立恢复。分支显式继承来源有效选项，不另增存储或同步服务。
- 限制：本浏览器、当前 origin 的本地保存，不属于服务端备份；不保证浏览器清理/驱逐或未提交事务的恢复，不做跨设备同步。多用户或多个 bot 共用 origin 时需分区键空间。可见追问队列与持久任务保持独立待办。

## ADR-018：计划先作为结构化产物快照（2026-10-04）

- **问题**：Codex 原生计划通知被忽略，Claude TodoWrite 只显示普通工具结果；已经打开的产物停留在点击时的内容。
- **决定**：引擎报告的完整计划经内部 `plan_update` 写进现有 AgentUX artifact 事件；每个 run 一个稳定 id，以 data 替换快照。显示时复用 Markdown 输出，按所属 run 的终态标注停止/失败，保留引擎最后报告的步骤，不补推完成。产物标签以 id 跟随更新，不以文件名混合多轮状态。
- **约束**：最多 100 步，每步 4000 字符；无效快照不覆盖已有计划。无新组件、依赖、路由或数据库；任务依赖和委派汇总的产品入口尚未接入。
- **原生入口补充**：Pi 增加纯数据 `update_plan` 工具，成功执行后才发出快照；原七个 I/O 工具仍走隔离 worker。Claude 显式启用 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`、`CLAUDE_CODE_ENABLE_TASKS=1`，剔除父会话的 `CLAUDE_CODE_TASK_LIST_ID`，按实际 CLI 顶层 `tool_use_result` 投影任务。task id 保存在产品快照中；只在同一原生 session 的 resume 中初始化，不给冷启动编造旧任务。原生 `.claude/tasks` 随 session 备份/迁移；产品快照不承担原生任务执行状态的所有权。
- **证据**：当前 Codex 0.153.4 生成的 v2 协议及其[配置 schema](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/core/config.schema.json)；显式开启 `tools.update_plan.enabled`，由实际 CLI 和本机受控 Responses 服务验证通知与原有审批。OpenMuse 的步骤状态和 nightly OpenBot 的事件所有权仅用作行为参考。

## ADR-019：历史读取错误只进入显示层（2026-10-04）

- **问题**：历史请求失败被吞掉后显示空会话；若直接往会话事件数组追加提示，会污染实时重接游标与轮次状态。
- **决定**：按会话保存读取结果，复用现有错误事件与视图，只在 replay 输入上附加通知；重试成功即移除，不落盘、不改变原事件。服务端 404 只有在本地确有未接受草稿时才能视为未创建会话。
- **范围**：移除客户端 100 条元数据截断，正文仍按需读取；不增加历史数据库或新错误组件。实际 HTTP/存储与浏览器验收见 [08 M 组](08-acceptance.md)。

## ADR-020：PDF 复用原生阅读器与既有文件生命周期（2026-10-04）

- **问题**：工作区 PDF 被按文本读取并显示错误或二进制内容；已有文件入口无法阅读正文。
- **决定**：沿用现有受限下载接口，验证文件头并生成明确 MIME 的本地 Blob，在既有输出视图中嵌入浏览器阅读器；下载始终可用。不开新路由，不把原始文件以 HTML 打开，不加载模型提供的外部 PDF 地址，不引入 PDF.js 或另一套阅读器组件。
- **参考**：OpenMuse 固定版本的 [PdfReader.web.tsx](https://github.com/CopilotKit/openmuse/blob/b06caad7005ac5b6d2b451752a3794a6ae1759c1/apps/mobile/src/PdfReader.web.tsx) 也使用原生 iframe；[HTML 的 PDF 支持接口](https://html.spec.whatwg.org/multipage/system-state.html#pdf-viewing-support) 用于无支持时提示下载。本机内嵌浏览器即使报告支持仍显示空白，因此不把能力标志当作渲染成功证据。
- **限制**：Chrome 的桌面/390px 两页阅读和损坏文件恢复已实测；内嵌浏览器兼容性未完成。结构损坏、密码和原生阅读操作由浏览器处理，文件头校验不冒充完整 PDF 校验；真机、加密文档和表单填写仍未验收。若产品必须在缺少原生阅读器的目标客户端内阅读，再评估独立的惰性加载解析模块。

## ADR-021：用户提问与工具权限分开等待（2026-10-04）

- **问题**：真实 Claude CLI 在 allow-all 下把 AskUserQuestion 当作普通获准工具，返回“用户未回答”并继续；Codex 默认模式列出工具却返回 unavailable。一般权限批准不能代替用户给出任务信息。
- **决定**：复用主机、现有事件存储与现有选项/文本控件；用独立的小 gate 等待回答，原生引擎各自转换格式。Codex 0.153.4 的本机 features / generate-ts 与实际 CLI 验证默认模式开关；不改变模型或权限策略。参考 nightly OpenBot 的问题/审批分流原则，独立实现，不复制许可受限代码。
- **恢复边界**：问题与已提交回答立即落盘；页面/传输断开不替用户回答。重启标中断、不重放；100 个内存确认回执只解决活进程内重试。无新服务、数据库、依赖或 UI 组件。未提交表单的刷新丢失于 AE 组补修：使用原生 sessionStorage 保留当前标签页的选项、文字与题目进度；问题身份隔离、保存失败可见，恢复不等于提交，不同步其他标签页或设备，也不承诺关页后保留。已提交答案仍以主机事件为准。
- **验收**：三引擎本机协议闭环、原有 Codex 副作用审批回归及真实浏览器见 U 组；外部模型自主提问与新模块云端隔离验证仍待做。

## ADR-022：摘要与正文缓存分开，待写事件不参与淘汰（2026-10-04）

- **依据**：600 份约 150 MiB 正文经一次 list 后仍占约 150 MiB 堆；前端列表窗口化不能解决主机的无限 Map。
- **决定**：保持原 JSON 文件与同步写入边界，完整摘要留在内存，已保存正文按最近使用保留 12 份；待写记录单独保留，成功写入后归回可淘汰集合，失败清除未提交缓存。独立 30 行模块，不引入索引数据库或持久缓存。
- **边界**：按记录数限制，单个长会话及同时待写记录仍可很大；冷列表/启动和全文搜索仍逐文件扫描，热摘要假设应用进程独占目录。重新读取被淘汰正文可能暴露其磁盘读取失败，继续沿用现有错误反馈，不能把它当作空历史。实测与回归见 AP 组。

## ADR-023：模型服务偏好只保存用户修改的非密钥字段（2026-10-04）

- **问题**：现有模型设置仅改 React 内存，刷新回到项目初始值；主机初次配置也直接读取静态项目。
- **决定**：复用原生 localStorage，校验已知服务及可编辑字段，只保存相对部署默认的修改；恢复后的项目同时供现有控件和主机配置使用。会话 key 继续仅在内存中，含凭据信息或查询/片段的地址不持久保存；不保存完整项目或另建服务端配置接口。
- **边界**：读失败明确使用项目默认值，初始化不覆盖旧值；写失败保留当前页修改并显示未保存。当前单用户、每个 bot 独立 origin，多个标签页采用最后一次完整保存，不自动改变其他标签页正在使用的模型；不是跨设备同步或沙箱备份。只借鉴 nightly 设置状态须区分保存/失败和明确归属的原则，未复制其服务端保存实现；验收见 AQ 组。
