## 已实现行为

- 保存配置会把非秘密配置和密钥一起提交给主机；主机原子写入成功后页面才应用。新浏览器、刷新和主机重启都从主机读取配置。首次旧浏览器偏好只在用户显式保存时导入，不自动覆盖主机。
- API 密钥输入框留空保留、输入新值替换。删除是单独的草稿操作，可撤销，统一点击保存后生效。停用 provider 不删除凭据。
- 保存成功清空输入框，只显示“已保存在主机”，不回传明文、片段或密文；显示按钮仅查看未提交输入。保存失败保留草稿，版本冲突需要放弃草稿后重新编辑。
- 凭据绑定 provider ID、规范化 endpoint、协议和鉴权模式。更改 URL 不会转发旧 key；恢复旧绑定仍可使用旧 key。省略或清空新输入不会删除旧绑定。
- Pi、Claude/Codex/DSH 的 provider 解析、模型列表测试和标题生成共用存储；每个 Pi 轮次重新解析并清除失效的运行时 key。保存/删除清除旧浏览器临时缓存，运行中拒绝保存。
- IM 与例行任务明确只读持久密钥或主机环境变量，不继承网页临时 key。它们已有的模型选择快照不因保存其他 provider 而擅自切换。

## 存储与安全边界

`<RAYTONEBOT_DATA_DIR>.provider-secrets/` 是数据目录的同级私密目录（默认 `~/.raytonebot/data.provider-secrets/`）。目录 0700，文件 0600，拒绝符号链接、不安全权限及不属于当前 UID 的文件。

- `providers.enc`：AES-256-GCM 加密的配置及密钥，每次写入随机 nonce，认证附加数据固定格式版本。凭据绑定在受认证的内容中。
- `master.key`：首次保存时生成的 32 字节随机主密钥，单独保存。若设置 `RAYTONEBOT_CREDENTIAL_MASTER_KEY`（64 位十六进制），使用该部署侧密钥，不生成文件。主密钥必须跨重启保持不变；已有密文但主密钥丢失/错误时拒绝打开，不重建空库。
- 原子临时文件写入与 fsync 后 rename；独占写锁和 revision 拒绝跨页面/进程覆盖。损坏文件保留，管理接口返回不可用。进程在持锁时崩溃可能留下 `providers.enc.lock`；确认没有其他保存进程后由运维移除锁文件，再重启，禁止删除密文来“修复”。
- GET/POST `/__agentcanvas/pi/providers` 沿用同源、云端入口鉴权、body 上限和 no-store；GET 返回配置、revision、每项 has-key 状态。密钥只经显式 POST 进入主机。私密目录加入工具及工作区排除路径；主密钥环境变量加入子进程过滤。
- sandbox 保存前检查现有 Linux 隔离配置。AgentSphere 的独立 Agent UID、受保护目录与防火墙是实际隔离边界。AgentMatrix 尚未完成同等隔离，不把其首期部署当作安全验收。

准确的保护范围：加密能防止仅误拷 `providers.enc` 导致明文泄漏；默认主密钥与密文位于同一个受保护目录，复制整个目录或控制主机用户仍可解密。这里没有实现 macOS Keychain/KMS，也不能防御已被攻陷的主机。本机同 UID 的 Agent 与主机仍非强隔离；云端依赖独立 UID 与现有网络隔离。

## 部署、备份与恢复

- 浏览器刷新、Node 重启、同一 sandbox 暂停恢复、替换应用代码：私密目录不变，无需重填 API key。
- AgentSphere 部署脚本保留外部 `RAYTONEBOT_CREDENTIAL_MASTER_KEY`，不会用新随机值覆盖；文件模式自动生成的主密钥不在应用目录，不随应用替换。AgentMatrix 同理需保留工作区内数据同级的私密目录，但其隔离仍待补验。
- 普通会话/工作区备份不含此同级目录，也不含主密钥。销毁后新建 sandbox **不会凭空恢复密钥**：须通过可信运维渠道另行备份并恢复 `providers.enc` 与匹配的主密钥，或使用持久卷/稳定部署 Secret。密文和主密钥应分开保管，不放源码、发布包、聊天或普通工作区备份。
- 本轮未增加跨实例凭据同步、自动秘密备份或平台 Secret 管理接口，也未操作/销毁用户的线上实例。
