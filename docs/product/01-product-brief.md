# 01 产品定义

## 一句话

一个部署在廉价云沙箱里的个人 AI 工作助手：电脑关机后它仍在，任务过程透明，修改操作先问人。

## 目标用户

首版只有一个用户：项目所有者本人，使用三个预置 Agent 角色及各自工作目录、一个共享目录。多用户、团队共享不在首版范围。

## 为什么用 AgentSphere 沙箱而不是 VPS/VM

- 成本低，按需创建，秒级启动（实测约 2 秒）；暂停/恢复约 1.2 秒且保留整机状态。
- Agent 的 shell/文件工具天然被关在 Firecracker microVM 里，不碰本机。
- 代价：单次运行最多 50 小时、暂停后访问不会自动唤醒、单台物理机、无故障自愈。**沙箱是可丢弃的**，产品必须能从备份和脚本重建（见 [06](06-deployment-runbook.md)）。

## 核心使用闭环

```
下达任务 → 流式查看思考/文本/工具调用 → 审批修改类操作 → 查看/下载产物 → 关掉浏览器，下次回来接着用
```

## 功能清单与优先级

P0 = 首个可用版本必须有；P1 = 紧随其后；P2 = 需求明确后再做。状态以 [03-roadmap.md](03-roadmap.md) 为准。

| 功能 | 优先级 | 现状 |
| --- | --- | --- |
| 对话 + 流式文本 + 思考过程 | P0 | 已实现，本机与云端真实模型通过 |
| 工具调用卡片（read/bash/edit/write/grep/find/ls） | P0 | 已实现，真实执行通过 |
| 修改前审批（request / auto / allow-all） | P0 | 已实现 |
| 停止任务、新建会话 | P0 | 已实现 |
| 服务端持有模型凭据，开箱即用 | P0 | 已实现（沙箱 env 文件） |
| 会话持久化：刷新/重启后恢复列表与历史 | P0 | 已实现（本机与云端验证） |
| Agent 工作区与应用代码分离 | P0 | 已实现（云端角色目录；本机未设置时仍为应用目录） |

## 非目标（首版明确不做）

- 不引入 OpenAgentCore、CopilotKit Intelligence、nightly openbot 或任何第二套会话后端。
- 不做多租户鉴权、计费、管理控制台。
- 不追求沙箱高可用；可用性靠“能快速重建 + 数据有备份”。
- 不重写 UI；现有组件覆盖了 Agent 的全部状态，优先修事件映射。

## 成功标准

1. 在云端 URL 上完成一次真实任务：读文件 → 提出修改 → 审批 → 写入 → 产物可见。
2. 关闭浏览器、重启服务后，会话列表和历史仍在。
3. 沙箱被销毁后，用一条命令在 15 分钟内重建并恢复最近备份。
4. 任意一个 P0/P1 功能，AI 按 [05](05-ai-workflow.md) 的流程能在一个工作会话内完成并通过 [08](08-acceptance.md) 的对应检查。
