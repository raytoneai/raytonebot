# 01 产品定义

## 一句话

一个单用户 AI 工作助手：在浏览器中下达任务，查看执行过程，按权限模式确认操作，并保存会话和工作产物。可在本机运行，也可部署到云端。

## 用户与使用场景

首版服务项目所有者本人。内置三个 Bot 作为起点，也支持创建 Bot、设置人设/模型/能力、修改名字和头像、邀请成员加入同一对话。Bot 的配置身份与引擎角色分开；同引擎 Bot 共用角色工作区，不是独立系统用户。多用户、团队共享不在首版范围。

典型任务包括查资料、读写文件、规划与实现代码、生成可预览的内容，以及通过 IM 或例行任务继续工作。云端运行不依赖用户电脑保持开机，但主机休眠会暂停执行；“部署在云端”不等于持续在线。

## 核心使用闭环

```
下达任务 → 查看文本/思考/工具过程 → 处理审批或提问 → 查看/下载产物 → 下次打开会话继续
```

## 产品范围

以下描述产品能力与边界；具体实现进度见 [03](03-roadmap.md)，验证条件见 [08](08-acceptance.md)。

| 范围 | 用户得到什么 |
| --- | --- |
| Bot 与引擎 | 内置 Pi、Claude Code、Codex 角色，自建 Bot 与本机可选 DSH；每个会话保持自己的上下文 |
| 任务控制 | 执行过程可见，支持审批、提问、停止和追问队列；不自动重放结果不明的任务 |
| 会话历史 | 刷新与重启后恢复，搜索、重命名、删除；支持具备原生定位的引擎历史分支 |
| 文件与产物 | 上传、下载、工作区浏览、代码/Markdown/媒体预览、交互 HTML、结构化表单和本地文档引用 |
| 多 Bot 协作 | 同一对话邀请成员、固定协作流程、任务负责人和结果回收，一层只读后台委派；不承诺通用自治组织或任意依赖调度 |
| 连接与记忆 | Telegram、飞书、钉钉、企业微信，按 Bot 分配的远程 MCP/文本 Skills，全局/Bot/群记忆及用户引用的聊天回查；各平台真实账号验收单独记录 |
| 例行任务 | 主机运行期间按时执行，结果落入普通对话；休眠期间依赖外部唤醒，不自动补跑错过场次 |
| 浏览器 | 有配套浏览器环境时可查看、操作、接管和交还；Login Vault 单次授权填入、不自动提交；不包含整台电脑/VNC |
| 部署与数据 | 模型配置与密钥由主机持久化，Provider/Vault 私密目录需单独恢复；工作区与应用可分离，部署与恢复依目标环境分别验收 |

## 运行环境

本机用于开发与个人任务，默认以当前用户权限运行。AgentSphere 路径提供 microVM、独立 Agent/browser UID、网络隔离和备份脚本，平台限制见 [运维手册](06-deployment-runbook.md)。

AgentMatrix 已有保留现有 Node 主机的首个部署，仍需补齐浏览器依赖、隔离、常驻与恢复要求；以 [部署记录](../agentmatrix-deployment.md) 区分已实现路径和 [迁移目标](../agentmatrix-hosting-minimal-requirements-2026-10-19.md)。

## 非目标

- 不引入 OpenAgentCore、CopilotKit Intelligence、nightly openbot 或第二套会话后端。
- 不做多租户鉴权、计费或团队空间；`control/` 是独立的欢迎/管理原型。
- 不承诺沙箱高可用；恢复能力必须由备份与实际重建验收证明。
- 不为已有 Agent 状态重写 UI；功能扩展沿用现有组件所有者。
- 邮件、日历、语音与专用 Git 提交面板不属于当前核心范围。

## 成功标准

1. 在目标环境完成真实任务：读文件 → 提出修改 → 审批 → 写入 → 产物可见。
2. 关闭浏览器、重启服务后，会话列表与历史仍在，原生上下文可继续。
3. 停止、拒绝、断线和存储失败有明确结果，不静默丢失输入或重放任务。
4. 实例丢失后可恢复必要数据；恢复时间与允许的数据丢失范围必须有目标环境证据。

这些是验收目标，不代表每种引擎和部署环境均已通过。
