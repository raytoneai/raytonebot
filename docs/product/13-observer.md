## 目标与现状

Observer 是开发者模式下可见的系统 Bot。它能读取本实例的整个仓库代码及跨 Bot 运行证据，解释异常、提出项目改进建议，并向 RSL 提交待审核经验。整仓和跨 Bot 是能力范围，分页、时间窗与预算控制单次读取量；不能把成本控制实现为永久限制只能观察一个 Bot。

首版针对每个实例自身的数据：本机、sandbox、VPS 各观察自己的运行版本，不自动连接其他实例、持有部署凭据或汇集远程数据。

| 基线已有能力 | 依据与使用限制 |
| --- | --- |
| 无工具 RSL 提议与批准经验复用 | [review.ts](../../src/pi/learning/review.ts)、[service.ts](../../src/pi/learning/service.ts)：单次有界请求，默认关闭；不自动获得 Observer 的数据权限 |
| 来源与权限快照、工具决定日志 | [runProvenance.ts](../../src/pi/runProvenance.ts)、[hostOperations.ts](../../src/pi/hostOperations.ts)：主机记录已观察事实；日志有界、尽力写入，不是完整或防篡改账本 |
| 讨论只读、停止与重启中断显示 | [groupChat.ts](../../src/pi/groupChat.ts)、[cancelledTurns.ts](../../src/runtime/cancelledTurns.ts)：复用既有行为，不重复排为缺失功能 |
| 例行任务等待和业务报告 | [架构说明](02-architecture.md)：模型自报的业务结果与主机执行终态分开，不能据此认定业务成功 |
| 开发者设置与调试 fixture | [SettingsDialog](../../src/components/settings/SettingsDialog.tsx)、[agent-shell](../../src/agent-shell.tsx)：已有 RSL 分区；`?devtools=1` 受开发构建限制，不能充当线上 Observer 入口或授权 |
| 本机控制面与云端入口 | [requestOrigin.ts](../../src/pi/requestOrigin.ts) 放行无 Origin 请求；[云入口](../../scripts/cloud-preview.mjs) 另有鉴权，Linux 隔离另有网络规则，不能据本机行为推断云端已可绕过 |

不在本计划内：自动改代码/人设/权限、自动部署、训练模型权重、新后端或数据库、向量检索、跨实例调度、通用 Routines observe 档、全局通知聚合、四引擎原生 session 解析。出现必须依靠原生记录才能回答的具体问题后，再独立评估适配。

## 执行分层与模块归属

| 层 | 输入与执行 | 输出 | 归属 |
| --- | --- | --- | --- |
| 现有 RSL | 原任务摘录；单次无工具请求 | 同 Bot/同引擎经验候选与批准后复用 | 原 `src/pi/learning/`，保持 ADR-056 的执行边界 |
| L1 统计解释 | 主机先计算有来源的统计；一次无工具请求，无重试、无备用模型 | 异常解释、证据缺口、待审核建议，也允许无发现 | 新 `src/pi/observer/` 内的统计与解释实现 |
| L2 诊断 Agent | 复用 Pi SDK 执行能力，但只组装 Observer 查询工具；每次查询经统一主机检查 | 有证据的诊断、项目建议或经验候选 | 同一 `src/pi/observer/`，通过现有 controller/事件链展示 |

L2 不给 RSL 加工具，也不继承普通 Pi Bot 的 bash/write/edit、浏览器、外部 MCP、频道、例行创建或委派工具。禁用内置工具及个人扩展发现；引擎选择固定为现有 Pi 接入，不为 Observer 新增引擎类型。复用现有模型配置，首次启用记录实际 provider/model；无可用配置则不可运行，不更换任何 Bot 的默认模型，不静默回退。

复用同一个 Node host、文件存储、模型网关和事件适配。L1/L2 可共用证据、预算及报告实现；RSL 只通过显式、校验后的候选入口接收经验，不共享可变 Agent 上下文。

<a id="experience"></a>

## 入口、可见性与开关

- `SettingsDialog` 的开发者分区拥有开发者视图、Observer 手动启用、后台观察、预算、报告审核与停用。用户控制面授权后才能更改；全部新功能默认关闭。
- 开发者视图开启且 Observer 启用后，`SessionSidebar` 展示系统 Bot；聊天沿 `ChatFrame`/`ComposerFrame`，报告和证据沿 `OutputFrame`，操作审批沿 `chatframe/approval.tsx`。不新增平行面板、聊天窗口或文件浏览器。
- 普通模式不返回 Observer 的 Bot 条目、诊断历史、搜索结果或产物。主机统一约束列表、按 ID 读取、搜索、实时流、导出/下载及聊天引用；前端过滤仅负责展示。切回普通模式撤销该用户会话的开发者读取范围，停止相应流并清除页面中的证据缓存。
- 显隐不控制已显式启用的后台任务。关闭后台观察立即撤销后台运行；停用 Observer 撤销所有 Observer 查询能力并取消排队/运行。关闭视图、停用观察、停用批准经验复用三种效果在设置文案中区分。
- Observer 由主机保留系统身份；普通 Bot 新建、导入、改名或 HTTP 参数不能制造该身份。首版不开放群成员邀请、`@`、IM 绑定、委派或例行任务调用 Observer。
- 已批准并限定范围的经验可以注入普通 Bot，但不能顺带授予读取 Observer 报告的权限。显式交给开发 Bot 的 finding 使用单独、限次/限范围的只读交接能力。

<a id="authorization"></a>

## 控制面授权与固定前置范围

Origin/Host 检查用于来源与 CSRF 防护，不能代替身份认证。新增管理写入及已有敏感管理写入必须识别有效的用户控制面授权；模型网关租约、Agent 工具桥、query capability 都不能调用设置、批准经验或批准建议接口。不是把全部管理写接口关闭后让正常页面失效。

批次 0a 固定盘点本基线的 Node HTTP 路由、provider proxy、云入口及内部工具桥，按“公开最小健康信息／用户读取／用户管理写入／绑定轮次的 Agent 能力”分类，记录方法、路径模式、调用方、当前保护和目标保护。管理范围包括模型配置、Bot、权限、频道、例行任务、MCP/Skills、记忆、Vault、RSL 及新增 Observer；用户输入、停止、聊天/文件操作也必须在清单中归类，避免留下另一条提权入口。修复清单中未经授权的控制面访问，不扩展为任意操作系统安全审计。

批次 0b 建立统一主机授权检查：云端复用已经验证的入口身份并以受信任内部上下文传递，外部同名头必须剥离；本机建立主机签发、可撤销的用户会话，不向未授权 GET 页面或公共启动接口直接返回可用管理凭据。本机首次会话采用用户主动打开主机生成的一次性入口换取会话，入口只经主机启动的用户通道交付，不暴露为可匿名查询的 endpoint。入口秘密通过 URL fragment 交给页面，立即清除地址栏/当前历史项后用 POST 交换；不写普通日志、Agent 环境或工作区，不随 Referer 发送。会话使用 HttpOnly cookie；云端 HTTPS 加 Secure，本机仅 loopback，并保留同 UID/已控制浏览器的限制。写请求同时执行会话与 CSRF 校验，正常页面沿同一授权继续工作。凭据交换、过期、退出与开发者范围撤销都在固定测试矩阵内；不另建账号服务。

主机填写 `requestedBy`（`user_session` / `background`）和 `authorizedVia`（实际接受的控制面会话或关联后台配置授权记录），记录范围、版本、时间及接受/拒绝原因，不保存凭据值。模型和请求体自报的来源不得覆盖这些字段；认证证明授权通道，不证明生物意义上的人。

验收重点是未授权本机 HTTP 自批失败、已授权 UI 成功、Agent 能力不能兑换控制面权限，以及可信凭据下发链不会通过未授权入口泄漏。固定案例及实际通过状态在 [OB-00](08-acceptance.md#obs-00) 维护。不能只测试错路径 404，或只加一个可从普通页面读到的头。

同 UID 本机进程可能直接读取内存/文件、控制用户浏览器或篡改记录；本方案不承诺进程级不可绕过、防篡改审计或能阻止任意本地恶意进程。云端需分别验证 UID、网络、入口与受控浏览器不能绕到用户控制面；不把开关和日志当物理隔离。任何尚未通过的部署不得开放 L2。

<a id="queries"></a>

## 只读查询与事实生成

主机签发不接受模型自报的运行能力，绑定 `observerRunId`、实例、来源集合、查询类型、权限版本、预算、有效期与取消信号。多个类型明确的查询入口共用一个执行检查函数；不能各写一套校验，也不要求为了工具数量为一而引入万能查询语言。

| 查询范围 | 返回内容与限制 |
| --- | --- |
| 仓库 | 版本化可读清单、目录、字面搜索、有界行段；覆盖源码、测试、文档、脚本、依赖声明及需要检查的 vendor，只读不改冻结依赖 |
| 跨 Bot 会话 | 主机可见的公开 user/assistant 消息、标准工具生命周期、审批与终态；按实例/会话世代/轮次/事件身份关联，群和委派通过公开投影关联，不开放通用隐藏子 session 原文 |
| 运行与例行记录 | 结构化错误、等待、决定和运行元数据；明确日志轮转、缺失、旧格式和采样范围，不把未记录当未发生 |
| 配置与用量 | 脱敏的能力配置和版本、模型标识、实际报告用量；不含 env 值、Provider/Vault/CLI 登录凭据或账号会话 |

每次执行都检查调用能力、启用状态、作用域、路径真实归属、符号链接/路径穿越、来源是否删除、版本/游标、并发预算与取消状态。文件从已核验句柄有界读取，读取前后变化则拒绝该证据；拒绝记录固定原因码及关联 ID，不记原始参数或秘密。不接受任意 URL、SQL、shell 或任意磁盘路径。

授权范围与搜索命中分开：可搜索整仓与多个 Bot，但先定位再分页；目录清单和精确路径读取同样可用，不强制必须先 grep。忽略的秘密文件、主机私有目录、原生隐藏推理和浏览器登录态永不进入查询。源代码可能含硬编码秘密，路径过滤不是通用 DLP；发送模型前做有界脱敏/疑似秘密拒绝，并在启用时说明代码和允许的证据会发送至所选模型服务。

L1 的统计由代码产生，包含指标定义版本、分子/分母、时间窗、样本数、完整度与证据引用。执行失败、用户取消、主机中断、业务结果分别计数；审批拒绝不自动算业务失败。首轮覆盖执行错误、审批/策略拒绝分布、例行连续失败或耗时异常；没有错误码、历史基线或完整样本时明确缺口。

模型不能写入或改写 `facts`，只可引用本轮主机已签发的 fact ID 并填写解释。保存前验证 ID 属于本轮、范围、快照，且来源仍存在。主机事实只能证明“记录观察到了什么”；工具成功、正常终态、助手自称完成都不能升格为业务成功。

<a id="data"></a>

## Finding 与版本契约

首版即使用带 `schemaVersion` 和并发 `revision` 的记录，不靠后续从自然语言回填归属。结构字段归主机；模型输出经校验后才能成为解释和建议。

| 字段 | 约束 |
| --- | --- |
| `id`、`revision`、`observerRunId`、`kind` | 主机生成；`kind` 为项目建议或经验候选；本次运行标记为 L1/L2 |
| `requestedBy`、`authorizedVia`、时间、`instanceId` | 主机来源；后台关联当时启用配置及其 revision，不假装用户逐条批准 |
| `model`、分析指令版本 | 实际 provider/model/config revision，无秘密；模型身份未知则明确未知，不据配置猜实际调用 |
| `buildStamp`、`readScopeHash` | 实际观察版本及可读集合身份，含部署/本机差异说明 |
| `querySet` | 查询类型、脱敏且有界的结构参数、查询实现版本、时间窗、来源版本和返回证据 ID；不复制原文。不能完整保留的参数显式标为不可完全重现 |
| `facts`、`evidenceRefs` | 主机生成的结构化观察及引用；模型仅选用已签发 ID，不得自报事实 |
| `inference`、`proposedAction` | 有界解释文字；动作由枚举、类型化目标、预期改变/验证引用组成，不包含可直接执行的任意命令、脚本或补丁 |
| `budgetSpent` | 已发模型请求、查询次数、返回字节、耗时、供应商实际 token 与未知用量；不是账单或推算出的确定价格 |
| `reviewStatus`、`validity`、实施/效果引用 | 审核为 pending/accepted/rejected/disabled，有效性为 current/stale/evidence_missing；实施与效果另附证据，不能从 accepted 推导完成。RSL 仍使用原 pending/approved/rejected 语义 |
| `dedupKey`、`supersedes` | 主机按类型、作用范围、关联目标和证据身份生成；替代关系显式保存，合并/替代不继承旧批准 |

证据引用形式：代码使用清单内相对路径、内容哈希及行范围；会话使用实例、会话世代、run/message/event ID 及内容版本；日志使用段身份、记录定位与摘要哈希；聚合引用查询版本、窗口、源记录集合摘要和可追溯依赖。哈希用于识别一致性，不作为访问授权；日志轮转或来源不存在时回查明确失败。

`proposedAction` 区分检查、修改代码、增加测试、调整配置、更新文档、提议经验。目标按类型绑定代码引用、允许的配置项、经验作用域等；不强制所有建议都有现存文件行号。解释可保留散文，但永远是待核查数据，不是授权指令。

构建/打包流程生成 `buildStamp`：Git revision（可未知）、dirty 状态、实际发布字节的逐文件哈希、规范排序的清单哈希、构建/发布标识。可读集合另含路径和文件哈希清单及自身哈希；清单不把自身纳入哈希，秘密不在清单中。由主机读取，UI 只显示所需摘要；不能只扩展 `appVersion.ts` 的版本标签。复用当前发布包与已有 release metadata，不为观察另复制整个仓库。

本机未构建/有改动时建立当前可读树身份；部署读取实际包内清单并在取证时核对文件字节。文件在运行中改变则不能把新内容写成旧 build 的证据。重新部署、代码/可读清单或相关配置版本变化，使相关建议 `stale`；首版可保守将该旧构建的建议全部待复核。来源丢失为 `evidence_missing`，时间窗超过该查询声明的有效期同样失效。历史观察可供开发者解释过去，但不得作为当前有效建议或复用经验；复核产生新版本，不自动继承批准。

<a id="retention"></a>

## 存储、上下文与删除

Observer 的主机结构记录放在 `<dataDir>/observer/`，独立 schema、原子保存，目录/文件为 0700/0600，排除普通 Agent 文件读取。初始最多保存 500 条 finding、结构报告正文合计 10 MiB；达到上限停收新报告并提示清理，不静默删除已批准建议。最小删除标记与依赖清理不得因报告额度耗尽而被跳过，运行元数据也须有界。完整构建清单在私有 `manifests/<hash>.json` 去重保存（最多 20 个被引用的清单，每份 4 MiB）；运行最多 500 条，普通状态写入上限 18 MiB，删除/终态保留至 24 MiB，加载上限一致。设置可显式清理无 finding 依赖的已结束运行；不会淘汰已有建议。原 `learning/state.json` 保留。既有 RSL 候选补可选全来源/有效性字段，兼容加载旧数据，不为旧数据编造证据。旧候选有源会话身份的也纳入删除联动；源缺失的候选停止复用，等待明确复核。

L2 首选内存 session：只保存结构化报告及必要的脱敏用户问题/最终解释，源码与会话工具结果、拼接模型上下文不进入普通 ConversationStore、全文搜索、产物快照或备份。诊断刷新后展示已保存报告，不承诺原生上下文续接；新的诊断重新获取证据。若 SDK 必须落盘，则使用主机私有临时目录，明确 TTL，正常结束立即清理、启动时清理崩溃残留，备份和搜索显式排除；未验证清理前不开放 L2。

证据片段由开发者按引用临时打开，使用既有 Output 只读展示，不顺手保存为新的聊天附件。持久化解释也可能包含派生内容，不能因不保存工具原文而免除删除责任。

主机维护源身份到 finding、诊断报告、经验候选及复用记录的依赖映射。删除源会话时，立即撤销相关读取和复用、取消使用该源的在途分析，再清理包含该源的派生正文及引用；多来源 finding 首版整体撤销清理，后续可从剩余来源重新分析。只允许保留不含正文的最小删除回执，不以 `stale` 标签代替内容删除。

删除失效标记先可靠保存；并发读取、迟到模型返回、后台保存、重启恢复必须复核，不能重新生成已删正文。存储失败时相应派生读取/复用拒绝并报告未完成清理，不能对用户宣称删除成功。聚合样本含被删源时撤销相关报告并重算，不静默保留旧的解释。

已注入其他 Bot 原生上下文、用户显式导出、外部模型服务及已有离线备份不能靠一次删除撤回。停止未来注入，标明已发生的复用；新建干净对话排除旧上下文影响。备份只纳入结构报告、依赖映射、删除标记及配置，不含临时模型上下文和控制面凭据；恢复后先处理删除/失效，后台保持关闭，不恢复排队任务。旧备份不是全局删除账本，单独恢复旧备份可能恢复旧内容，不能宣称跨备份擦除。

<a id="review"></a>

## 审核、交接与 RSL 复用

链路为：主机取证 → L1/L2 分析 → 待审核 finding → 用户采纳/拒绝 → 单独授权开发或批准经验 → 实施与效果回查。

审核卡片在原 owner 内展示具体动作、适用范围、有效性、证据片段及上下文入口，不能只显示标题。批准绑定 finding revision、证据/范围版本和批准的动作类别；保存失败不返回成功，变更后旧批准失效。

给开发 Bot 的交接只携带 finding ID、revision 和明确的实施范围。主机按本次授权签发受限回查能力；普通 Bot 猜中 ID 也不能读报告。开发 Bot 回查仍将正文、源码注释和用户消息当作不可信数据，执行前复核有效性；保留原工具审批，审核建议不自动批准写入、部署或扩大权限。ID 回查、结构化动作和人工审核只能减少指令混入，不保证消除提示注入。

经验候选经批准后进入 RSL，首版继续同 Bot/同引擎且任务相关才复用；跨 Bot 观察不代表全局注入。不自动写入用户记忆、SOUL、Skills 或代码。每次注入前检查候选状态、来源存在、有效性和范围，记录目标会话/轮次、经验 ID/revision；过期、删除、停用或冲突不再注入。效果评估使用相同模型/配置的新会话基线与候选对照，不用“流程跑通”证明收益。

<a id="follow-up"></a>

### 实施与效果记录

在原开发者设置 finding 内手动记录，报告在原 Output 展示，引用沿既有入口打开普通会话的实际轮次。`followUp` 使用独立 revision，不修改原 finding 的审核/有效性或 RSL 批准；历史 stale finding 允许补充后续结果，不因此恢复为 current。请求同时绑定当前 finding revision 与 follow-up revision，主机填写记录时间、用户身份与授权来源，保存冲突需用户显式重试。

实施包含 planned/in_progress/implemented/abandoned 状态、摘要和普通会话轮次引用；implemented 至少一条有效引用。效果包含 not_evaluated/inconclusive/improved/unchanged/regressed 判断、摘要、基线与候选引用，可记录成功标准、正整数样本量和成本备注；明确改善/无变化/退步要求两侧不同运行和成功标准。文字与引用有界，敏感内容拒绝。所有结果显示为**用户记录，未自动验证**；主机只核验引用存在、属于本实例公开普通会话、世代及会话元数据快照版本一致，不验证实施是否成功或模型/配置/新上下文是否足够可比，不把未知样本量/成本填为零。

候选接口仅返回可选轮次元数据，不返回原文，不接受 Observer 自身、隐藏 session、任意 URL/路径或伪造主机元数据。引用携带主机确认的来源身份与会话元数据快照版本（标题、更新时间及公开轮次事件标识），不是冻结的原文副本；继续会话或改名可能使版本变化，设置内提示当前匹配、已变更或尚未加载。删除仅被 follow-up 引用的会话时，清除受影响实施段；效果任一侧来源删除则清除整个对照段，包括结论、成功标准、样本量及成本。保留不依赖该来源的原 finding 与无正文清理回执。删除原 finding 证据仍遵循整体清理规则，不能靠 follow-up 保留派生正文。

<a id="scheduling"></a>

## 调度、预算与失败

手动诊断与后台观察分别配置，默认关闭；用户开启时看到模型、观察范围、数据发送范围和预算。L1 只向模型发送主机统计及必要引用，不发送完整源码/原文。跨 Bot 解释使用 Observer 明确选择的已配置模型，不能随某个样本 Bot 自动切换服务。

初始保守预算（实现任务可依据测试在该文档同步调整，不能暗改）：查询默认最近 7 天、允许多个 Bot；每页最多 100 条记录或 200 行代码且不超过 32 KiB；一次运行累计返回最多 256 KiB、查询最多 20 次。L1 一次模型请求、30 秒、1000 输出 tokens、64 KiB 响应；L2 最多 6 次模型请求、120 秒、每次输出上限 2000 tokens。新 Observer 每日模型请求总上限默认 10（UTC），单并发；失败/取消已发送的请求照计，供应商用量缺失记未知。现有 RSL 每日预算保持独立，设置明确显示两个额度及消耗，不冒充总 token/费用硬上限。

用户可在开发者设置显式放宽窗口和资源预算，能力对象保存本次预算快照，模型不能修改；有界阈值的校验及并发扣减在主机。输入上下文还必须符合已配置模型的上下文限制，超限停止并要求缩小查询，不静默丢弃证据后下结论。

后台由已持久化的终态/纠正等线索触发，累计 30 秒空闲后批量分析新增窗口；前台开始时取消后台。避免全历史定期重扫，不自动唤醒休眠实例。主机持久记录运行来源和已处理标识，排除 Observer/L1、标题生成等内部任务，防止观察自身或分析重复报告。队列有界且仅在内存，重启不补跑，未完成运行标中断；下一次新触发按水位和来源身份去重，不能把未分析成功写为已完成。

读取错误、证据不足、无异常、达到预算、取消、模型失败、存储失败分别返回可解释结果。Observer 的存储或模型故障仅停用相关观察能力，不阻断普通聊天；但影响删除/授权的故障必须对受影响读取和写入拒绝。不自动重试、不切备用模型、不把空报告当成功。

## 批次依赖与部署

任务与完成状态以 [T6.11](03-roadmap.md#t611) 为准。0a 是控制面清单及失败基线，0b 是授权修复和正反例；1 是证据契约、版本、失效/删除和私有存储；2 是 L1；3 是 L2 手动入口；4 是后台与经验闭环；D 是部署资料与平台验收。

0 与 L1 的纯统计/离线评测可并行，最小证据契约先稳定。L1 正式落盘依赖 1，开放管理/真实自动运行依赖 0b；L2 依赖 0b、1 和既有模型配置，后台依赖相应分析层与预算完成。L1 验证价值不必等待全部控制面修复；L2 权限验收不以 L1 有用代替。

部署沿现有 `scripts/agentsphere/`、`scripts/agentmatrix/`、`scripts/vps/`：复用发布包，补齐可读源码/测试/文档清单和主机 buildStamp。`docs/` 纳入 AgentSphere 上传集合单列变更，仍排除秘密、未跟踪私有文件及临时诊断副本；不要求远端携带 `.git` 历史。按各平台的包容量、目录权限、只读读取、更新/回滚版本一致性、备份/恢复逐项验收。AgentMatrix 的既有隔离与持久化缺口不能由文档或另一平台通过推定已补齐。

验收前标明实际 commit、dirty/清单哈希、模型配置、环境和覆盖范围；真实模型价值、浏览器展示、执行层权限与线上部署分别给出证据。本文不包含自动实施或部署授权。
