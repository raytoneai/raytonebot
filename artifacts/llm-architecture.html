LLM 架构解剖：MoE、MTP 和它们到底在解决什么

先把话说清楚：现在的大模型架构骨架几乎没变过 —— 一串相同的 Transformer 块叠起来。真正在变的只有三处：FFN 层怎么放参数（MoE）、注意力怎么省显存（MQA/GQA/MLA）、训练目标怎么加料（MTP）。

下面每个板块都能动手调。数字是教学示例，不是某个真实模型的规格 —— 除非标了出处。

01先看一个 Block

不管是 7B 还是 671B，都是这个积木重复几十层。所有架构创新，都是在这几个格子里动手脚。

  • RMSNorm —— 每层开头把数值拉回稳定范围。省掉均值计算，比 LayerNorm 便宜，现在几乎是默认选择。
  • 自注意力 —— 让每个 token 读到前面的 token。这里的变化最多（下一节讲），因为它决定了长上下文要多少显存。
  • FFN / MoE —— 占了全部参数的 2/3 以上，是真正的知识仓库。MoE 就是把这一块拆成很多份，每次只用其中一部分。
  • 残差连接 —— 让梯度能直着流回去。没有它，几十层根本训不动。

路由：一个 token 怎么选专家

每个 token 过一遍路由器（一个小线性层 + softmax），打分最高的 k 个专家被激活，其余专家的权重这轮完全不参与计算。为了看清，下图每个 token 固定画 2 条线。

MoE 的代价是什么？三个，都很实际：

① 显存不省。671B 参数就得按 671B 存。省的是算力和带宽，不是显存 —— 这是最常见的误解。

② 专家负载不均。路由如果偏爱某几个专家，训练会塌成"只用几个专家"，推理时那几张卡就成了瓶颈。DeepSeek-V3 的做法是给每个专家挂一个偏置项动态调整（auxiliary-loss-free），不靠额外的均衡损失去干扰主目标。

③ 通信开销。专家分布在不同 GPU 上，token 得被发送过去再收回来（all-to-all）。批次小的时候，通信反而成主导成本 —— 所以 MoE 天生适合大吞吐服务，不适合本地单机小批量。

03注意力：所有努力都在救 KV cache

推理时最贵的不是算力，是显存带宽 —— 每生成一个 token，都要把之前所有 token 的 Key/Value 读一遍。所以过去几年注意力的主线只有一件事：把 KV 缓存压小。

每 token 每层的 KV 缓存大小（bf16，示例配置 d=4096 / 32 头 × 128 维）

  • MHA —— 每个头独立存 K/V。表达力最强，缓存最大。
  • MQA —— 所有头共享一份 K/V。缓存降到 1/32，但质量掉得明显。
  • GQA —— 折中：8 个 query 头共享一组 K/V。Llama 2/3 的选择，性价比最高。
  • MLA —— 不存 K/V，存一个压缩后的 latent（512 维）+ 一小段解耦的 RoPE 维度（64 维），用时再投影回去。DeepSeek-V2 报告 KV 缓存减少 93%，效果反而比 MHA 好。

MLA 的关键 trick 是解耦 RoPE：位置信息必须和内容分开存，否则压缩后的 latent 一旦被旋转就无法再还原。所以它保留 64 维专门装位置，剩下的装内容。

另一条路线是干脆不全都看：滑动窗口注意力、DeepSeek 的稀疏注意力（DSA）用一个小索引器先挑出相关 token，只算这一小撮。代价是实现复杂度，收益是长上下文成本接近线性。

04MTP：一次不只猜一个 token

先说清楚归属：MTP = Multi-Token Prediction，是一种训练目标，不是网络结构。它不改模型主干，只是在旁边多接几个预测头。

MTP 模块 = 一个 Transformer 块 + 投影，把「已经确定的 t₁」和「ht」拼起来，再预测 t₂。这个模块可以顺序串 D 个，一路预测到 tD+1（DeepSeek-V3 用 D=1）。

为什么它对训练有好处？逼模型在做预测之前就"想到后面几步"。如果 t₂ 都要预测对，ht 里就不能只有 t₁ 的信息，必须提前编码计划的走向。这是把「规划」压进了表示本身。

为什么它对推理有好处？MTP 模块本身就是一个免费的草稿模型（draft model），可以直接拿去做投机解码。

关键：MTP 模块是可丢弃的。丢掉它，主干仍然是完整可用的语言模型。它不是架构的一部分，是挂在旁边的脚手架。

DeepSeek-V3 报告第二个 token 的接受率约 85%–90%，对应约 1.8 倍解码速度。

算法：主模型出 t₁，MTP 顺手猜 t₂；然后把 [t₁,t₂] 一起送进主模型做一次前向 —— 这一次同时验证了 t₂、并顺带算出 t₃ 的分布。猜对就白赚一个 token，猜错就退回去只保留 t₁（主干结果永远正确，所以这叫"无损加速"）。

三个容易搞混的点：

① MoE 不等于更小的模型。它省算力不省显存。一个 671B 的 MoE 跑起来，显存账单还是 671B 的。

② MTP 不是架构，是训练目标 + 加速手段。看到"某模型用了 MTP"，别以为是新的网络结构；主干和普通 Transformer 没区别。

③ 激活参数 ≠ 能力。37B 激活的模型打平几百 B 稠密模型，靠的是总参数里存的知识 + 路由选对了专家。所以别只比激活参数，那是成本指标，不是能力指标。
