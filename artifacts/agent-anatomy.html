一个 Agent 由什么组成

常见误解：以为 agent 就是一个更聪明的大模型。其实模型只是引擎，真正让它在现实世界里干活的，是引擎外面那一圈东西。

点击图上的任意节点，看它负责哪一段。

运行时循环

一次任务的每一"拍"，都绕这个圈走一遍。走得越久，干的活越多。

圈上的四步由中心那个模型驱动 —— 但模型本身不记住任何东西

GOAL

目标

一圈的起点。它不是一个模糊的念头，而是一句可验证的完成条件 —— 含糊的目标，会让后面每一步都在猜。

静态组成：搭一个 agent 要备齐的六样东西

上面那张图是"怎么转"，这六项是"拿什么转"。

模型 model

唯一的决策者。它读上下文，决定下一步说什么或做什么。能力上限、成本、延迟全由它决定。

→ 换个模型，agent 的性格和能力会变

指令与人设 system prompt

告诉它它是谁、给谁干活、边界在哪、怎么交付。这是唯一能稳定约束它的东西 —— 聊出来的规矩不算。

→ AGENTS.md / SOUL.md / 风格与格式约束

工具 tools

读写文件、跑命令、搜网页、调 API。工具是 agent 唯一能改变世界的通道，也是它唯一能获得新事实的通道。

→ 没有工具，它只能说话，不能做事

记忆 memory

短期是上下文窗口，长期是落盘的偏好与事实。上下文有限，所以"记住什么"永远是一道取舍题。

→ 没有记忆，它每次都从零开始

循环与编排 loop

决定它能自己走多远：走一步就停，还是连续试错十次。上限设多少，直接决定它是工具还是同事。

→ 单次问答 vs 自主推进，差别全在这

权限与沙箱 permissions

哪些动作可以直接做、哪些要先问人、哪些路径永远不许碰。这是你敢放它跑多久的前提。

→ 读文件放行，删数据和人点头

一次真实运行，逐拍拆开

用"帮我看看这个项目为什么构建失败"举例，走一遍这八拍。

01
输入 · 上下文
你发一句话。它变成 messages 里的一条 user 记录 —— 仅此而已。
02
编排 · prompt 拼装
指令、人设、长期记忆、历史、工具清单，被拼成一次请求。此刻模型看到的世界，就是你给它的全部。
03
模型 · 推理
它决定：先把构建日志读出来再说。于是输出一个结构化的工具调用，而不是答案。
04
权限 · 检查
读日志属于低风险，直接放行。换成删文件或对外发消息，流程会在这里停住等你点头。
05
工具 · 执行
真的去读了。可能成功，可能文件不存在，可能权限不够 —— 三种结果它都得自己面对。
06
上下文 · 回填
结果原样塞回 messages。注意：模型没有"记住"任何事，它只是重新读了一遍更长的上下文。
07
循环 · 再走一圈
回到第 03 拍。同一个模型、同一套工具，只比刚才多了一段日志。这就是 agent 和一次性问答的全部区别。
08
交付
给出结论，流式回到屏幕。值得留下的偏好写进长期记忆，下一轮才用得上。

最反直觉的一点：模型本身是无状态的。它不"记得"上一句话，也不"知道"刚才调用了什么工具。所谓记忆、上下文、会话，全部是外面那一圈在维护的。所以 agent 出问题，八成不是模型不够聪明，而是外面那一圈把错的上下文喂给了它。

判断一个 agent 好不好用，也别只问"用的什么模型"。问这四件事更准：给它的指令清不清楚、工具够不够用、上下文丢了什么、权限卡得合不合适。
